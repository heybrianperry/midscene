<rule_activation id="20110816-a01c-4244-897b-60c391362cb1" title="Enforce Environment Variable Validation with Zod Schema for Runtime Configuration: Configuration Schemas Use" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime configuration and environment variable handling. All modules that consume environment variables or external configuration MUST apply the validation rules defined herein.
</rule_activation>

### Rules

- **R-ZOD-001** SHOULD: Configuration schemas SHOULD use Zod's transformation capabilities (e.g., z.coerce) to handle type conversion from string environment variables.

### Verify

```bash
# Detect direct process.env access outside of configuration modules
grep -r 'process\.env\.' --include='*.ts' --include='*.js' --exclude-dir=node_modules | grep -v 'z\.object\|zod\|schema' | wc -l

# Count Zod imports in codebase
grep -r 'import.*zod' --include='*.ts' packages/ | wc -l

# Run configuration validation tests
npm test -- --grep 'configuration.*validation'
```

**Accept when:**
- All configuration modules use Zod schemas for validation with no direct process.env access in application logic
- CI pipeline includes tests that verify configuration validation behavior with invalid inputs
- Linting rules detect and flag direct environment variable access without validation
- Configuration schemas use z.coerce for type conversion from string environment variables
- Centralized configuration module exports validated config objects and their schemas
- Error messages clearly indicate which environment variable failed validation and expected format
- Both schema type and validated config object are exported from configuration modules

<enforcement>
Claude Code MUST verify Zod schema validation is applied to all environment variables and external configuration sources. Violations detected by ESLint rules, code review, or CI/CD pipeline tests MUST block merge. Exceptions require tech lead approval with documented risk assessment and remediation timeline.
</enforcement>
