<rule_activation id="1f29fb42-f4ff-4c98-8f5a-d2af4cbce997" title="Adopt Backend Client Integration Pattern for External Service Communication: Backend Client Implementations" applies_to="**/*">
These rules are ALWAYS ACTIVE for all external service integrations and backend client implementations across the codebase, including RDP backend clients in packages/computer, MCP tool integrations in packages/web-integration, and Electron packaging scripts in apps/studio.
</rule_activation>

### Rules

- **R-BCI-001** MUST: All backend client implementations MUST encapsulate connection logic in dedicated client classes or modules that abstract the underlying communication protocol.

### Scope

**In scope:**
- All RDP backend client implementations in packages/computer
- MCP tool integrations with external services like Puppeteer in packages/web-integration
- Electron packaging scripts that communicate with external build services or APIs
- Any new integration with external services, APIs, or backend systems
- Data access patterns that communicate with remote services

**Out of scope:**
- Internal module-to-module communication within the same process
- Direct database access using ORM or query builders
- File system operations and local resource access
- In-memory data structures and caching layers
- Pure utility functions without external dependencies

**Exceptions:**
- EXC-001: Proof-of-concept or prototype code that will not be merged to production branches
- EXC-002: Third-party SDK already provides a well-designed client abstraction that meets all MUST requirements

### Verify

```bash
# Identify backend client class implementations
grep -r 'class.*Client' packages/computer/src packages/web-integration/src apps/studio/scripts --include='*.ts' --include='*.js' --include='*.mjs'

# Verify typed client interfaces exist
grep -r 'export.*interface.*Client' packages/computer/src packages/web-integration/src --include='*.ts'

# Check integration test coverage for backend clients
npm test -- --grep 'backend.*client|integration.*test' 2>&1 | grep -E '(passing|failing)'
```

**Accept when:**
- All backend client classes are identified and implement typed interfaces with error handling
- Integration tests exist for client implementations covering connection failures and retry scenarios
- Code review checklist includes verification of backend client pattern compliance for new integrations
- New backend client implementations include required error handling and typed interfaces
- Architecture review approves integration approach for new external service integrations
- Integration test coverage for client modules meets minimum 80% threshold

<enforcement>
Claude Code MUST NOT skip or defer verification of backend client pattern compliance. All new external service integrations MUST be reviewed against R-BCI-001 requirements before approval. CI pipeline MUST fail if implementations lack required error handling or typed interfaces. Pull requests MUST be blocked until architecture review approves integration approach.
</enforcement>
