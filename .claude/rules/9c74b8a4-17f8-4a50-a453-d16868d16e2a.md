### Rules

- **R-IUT-001** SHOULD: Integration unit tests SHOULD be organized in dedicated test directories following the pattern `tests/unit-test/` or `tests/`.
- **R-IUT-002** SHOULD: Use test naming conventions that clearly identify the integration component being tested (e.g., `backend-client.test.ts`, `startup-smoke.test.mjs`).
- **R-IUT-003** SHOULD: Leverage testing frameworks' mocking capabilities to isolate external dependencies while maintaining realistic test scenarios.
- **R-IUT-004** SHOULD: Include smoke tests for critical integration paths to validate basic startup and initialization behavior.
- **R-IUT-005** SHOULD: Document the integration contract being tested in test descriptions to serve as living documentation.
- **R-IUT-006** MUST: Unit tests MUST execute successfully without requiring external service dependencies or infrastructure.
- **R-IUT-007** MUST: Test coverage for integration patterns MUST meet or exceed project-defined thresholds (typically 80%+).

### Verify

```bash
# Count integration unit test files
find . -path '*/tests/*' -name '*.test.*' -type f | grep -E '(integration|backend|client|smoke)' | wc -l

# Verify test structure and naming conventions
grep -r "describe\|test\|it" --include='*.test.*' --include='*.spec.*' | grep -i 'integration\|backend\|client' | head -5

# List integration tests by pattern
npm test -- --testPathPattern='(integration|backend|client)' --listTests 2>/dev/null || echo 'Test command varies by project'
```

**Accept when:**
- Integration pattern implementations include corresponding unit test files in `tests/` directories
- Unit tests execute successfully without requiring external service dependencies or infrastructure
- Test coverage for integration patterns meets or exceeds project-defined thresholds (typically 80%+)
- Test files follow naming conventions identifying the integration component being tested
- Integration contracts are documented in test descriptions
