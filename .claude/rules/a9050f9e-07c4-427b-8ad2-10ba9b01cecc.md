These rules are ALWAYS ACTIVE for all files matching frontend rendering components and E2E test scenarios across the project.
</rule_activation>

### Rules

- **R-PW-001** SHOULD: E2E test files SHOULD be organized by functional area (e.g., cache-functionality.spec.ts, narrow-input-prompt.spec.ts) for maintainability.
- **R-PW-002** SHOULD: Organize E2E tests in dedicated directories (e.g., tests/ai/web/playwright/) to separate them from unit tests.
- **R-PW-003** SHOULD: Create reusable Playwright fixtures for common rendering scenarios (navigation, storage, screenshots) to reduce test duplication.
- **R-PW-004** SHOULD: Implement CDP fallback patterns for browser features that may not be available in all contexts.
- **R-PW-005** SHOULD: Use descriptive test file names that clearly indicate the rendering scenario being validated.
- **R-PW-006** SHOULD: Implement Playwright's auto-waiting mechanisms and use explicit wait strategies to reduce test flakiness.
- **R-PW-007** SHOULD: Isolate tests from external network dependencies using mocks or fixtures.
- **R-PW-008** SHOULD: Pin Playwright and browser versions in CI and establish regular update cycles with regression testing.
- **R-PW-009** SHOULD: Parallelize test execution and implement test sharding to manage CI execution time.
- **R-PW-010** SHOULD: Run full E2E suite only on main branch while running smoke tests on PRs to optimize development velocity.

### Verify

```bash
# Count Playwright test files
find . -name '*.spec.ts' -path '*/playwright/*' | wc -l | grep -v '^0$'

# Verify @playwright/test dependency
grep -r "@playwright/test" package.json packages/*/package.json

# Verify test scripts reference Playwright
grep -r "test.*playwright" package.json packages/*/package.json | grep -E '(test|e2e)'
```

**Accept when:**
- At least one Playwright test file exists in the project with .spec.ts extension
- Package.json includes @playwright/test as a dependency
- Test scripts reference Playwright for E2E testing execution
- E2E test files follow naming conventions matching functional areas (e.g., cache-functionality.spec.ts)
- Tests are organized in dedicated directories separate from unit tests
