<rule_activation id="823b64d6-c1b6-4b25-a095-2133a4df4ed8" title="Adopt Service Client Integration Pattern for Backend Communication: Backend Client Implementations" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching backend client implementations, build scripts, and service integration code across the system.
</rule_activation>

### Rules

- **R-SCI-001** MUST: Backend client implementations MUST be encapsulated in dedicated client modules with clear service boundaries.

### Verify

```bash
# Find backend client implementations
find . -name '*client*.ts' -o -name '*client*.js' | grep -E '(backend|service)' | head -10

# Verify exported client interfaces
grep -r 'export.*Client' --include='*.ts' --include='*.js' packages/ apps/ | grep -i backend

# Find build scripts with service coordination patterns
find apps/studio/scripts -name '*.mjs' -exec grep -l 'wait\|health\|ready' {} \;
```

**Accept when:**
- Backend client modules are found in dedicated files with clear naming patterns (e.g., backend-client.ts, service-client.ts)
- Build scripts demonstrate service coordination patterns with wait mechanisms or health checks
- Client implementations export typed interfaces or classes for backend service communication
- Service boundaries are clearly defined and enforced between client and server logic
- Type safety is maintained in client-backend communication through TypeScript interfaces or type definitions

<enforcement>
Claude Code MUST NOT skip or defer verification of backend client module organization, service boundary adherence, and integration pattern consistency. All violations must be flagged for refactoring before merge.
</enforcement>
