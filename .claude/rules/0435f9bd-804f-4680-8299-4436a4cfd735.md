<rule_activation id="0435f9bd-804f-4680-8299-4436a4cfd735" title="Adopt Event-Driven Polling with Interval-Based State Synchronization: Polling Mechanisms Not" applies_to="**/*">
These rules are ALWAYS ACTIVE for all data access patterns involving periodic state synchronization, event optimization, and keepalive mechanisms across the codebase, specifically in browser extension background scripts, real-time streaming components, event optimization utilities, and client-side modules performing periodic health checks or state synchronization.
</rule_activation>

### Rules

- **R-POLL-001** MUST NOT: Polling mechanisms MUST NOT execute synchronous blocking operations that could freeze the UI thread.

### Verify

```bash
# Count setInterval/setTimeout calls without corresponding cleanup
grep -r 'setInterval\|setTimeout' --include='*.ts' --include='*.js' | grep -v 'clearInterval\|clearTimeout' | wc -l

# Verify setInterval calls have corresponding clearInterval
grep -r 'setInterval' --include='*.ts' --include='*.tsx' -A 10 | grep -c 'clearInterval'

# Check for polling/interval/keepalive tests with cleanup verification
npm run test -- --grep 'polling\|interval\|keepalive' --reporter json | jq '.tests[] | select(.title | contains("cleanup"))'
```

**Accept when:**
- All setInterval and setTimeout calls have corresponding clearInterval/clearTimeout in cleanup paths (component unmount, error handlers, connection close)
- Polling intervals are defined as named constants or configuration values rather than inline magic numbers
- Unit tests exist for polling mechanisms that verify cleanup behavior using fake timers (jest.useFakeTimers or sinon.useFakeTimers)
- Polling intervals include random jitter (±10-20%) to prevent thundering herd problems
- Browser extension keepalive mechanisms use chrome.alarms API for critical tasks
- Visibility change detection is implemented for background tab scenarios
