<rule_activation id="b6d30da6-e66e-4f8e-ad20-b16e40c1423f" title="Standardize Console Logging for Service Boundary Operations: Log Messages Use" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in service boundary contexts: Chrome extension background workers and service workers, recorder timeline components and state management, IndexedDB operations and data persistence layers, visualizer playground components with user interactions, server-side playground and development servers, cross-boundary communication and message passing, and asynchronous operations and promise chains at service boundaries.
</rule_activation>

### Rules

- **R-CONSOLE-001** SHOULD: Log messages SHOULD use appropriate console methods (console.log for info, console.error for errors, console.warn for warnings) to indicate severity.

### Verify

```bash
# Count existing console logging statements across service boundary files
grep -r 'console\.(log|error|warn|info)' apps/chrome-extension/src/scripts/ packages/recorder/src/ packages/visualizer/src/ packages/playground/src/ | wc -l

# Verify no sensitive data patterns in console logs
grep -r 'console\.log.*password\|console\.log.*token\|console\.log.*secret' apps/ packages/ || echo 'No sensitive data patterns found'

# Count files using console logging in service boundary contexts
find apps/chrome-extension packages/recorder packages/visualizer packages/playground -name '*.ts' -o -name '*.tsx' | xargs grep -l 'console\.' | wc -l
```

**Accept when:**
- Console logging statements are present in service boundary files (worker.ts, RecordTimeline.tsx, indexedDB.ts, universal-playground/index.tsx, server.ts) with appropriate context
- No console.log statements contain obvious sensitive data patterns (password, token, secret, apiKey)
- At least 80% of service boundary operations include logging for initialization, errors, or state transitions
- Code review checklist includes verification of logging practices and sensitive data exclusion

<enforcement>
Claude Code MUST verify console logging compliance through code review process checks, ESLint rules, automated grep-based CI pipeline checks, and manual audit of new service boundary code. Violations blocking merge if logging exposes sensitive data, ESLint warnings requiring justification, post-merge violations triggering immediate remediation, and repeated violations resulting in developer training. Exceptions require documentation of performance impact or technical constraint with team lead approval and quarterly review.
</enforcement>
