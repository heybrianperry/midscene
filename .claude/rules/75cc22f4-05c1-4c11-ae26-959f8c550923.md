<rule_activation id="75cc22f4-05c1-4c11-ae26-959f8c550923" title="Adopt Event-Driven Interval Management with Cleanup Handlers: Data Access Intervals" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files using setInterval, setTimeout, requestAnimationFrame, or event listeners in browser extensions, streaming components, and keepalive mechanisms.
</rule_activation>

### Rules

- **R-INTERVAL-001** SHOULD: Data access intervals SHOULD be configurable to allow tuning of polling frequencies based on use case requirements.
- **R-INTERVAL-002** MUST: All setInterval and setTimeout calls MUST have corresponding clearInterval or clearTimeout calls in cleanup handlers.
- **R-INTERVAL-003** MUST: Cleanup handlers MUST be idempotent and check state before clearing intervals to prevent errors from multiple invocations.
- **R-INTERVAL-004** SHOULD: Utility functions that start intervals SHOULD return cleanup handler functions to enforce paired setup/teardown patterns.
- **R-INTERVAL-005** SHOULD: Interval IDs SHOULD be stored in component state or closure scope to ensure accessibility for cleanup.
- **R-INTERVAL-006** SHOULD: TypeScript types SHOULD make cleanup functions required return values from setup functions.

### Verify

```bash
# Check for setInterval/setTimeout without corresponding cleanup
grep -r 'setInterval\|setTimeout' --include='*.ts' --include='*.tsx' | grep -v 'clearInterval\|clearTimeout' | wc -l

# Run ESLint rules for interval management
eslint --rule 'no-uncleared-intervals' src/

# Run tests verifying cleanup behavior
npm test -- --grep 'cleanup|teardown|unmount'
```

**Accept when:**
- All files using setInterval or setTimeout have corresponding clearInterval or clearTimeout calls in cleanup handlers
- ESLint rules for interval management pass without violations
- Unit tests verify that cleanup functions properly clear intervals and prevent continued execution
- No orphaned intervals or event listeners remain after component unmounting or connection termination
