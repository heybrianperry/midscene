<rule_activation id="68e92433-d978-44d6-b23d-f4e749755323" title="Enforce Environment Variable Validation with Zod Schema for Runtime Configuration: Application Code Not" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime configuration and environment variable handling in the codebase. All modules that consume environment variables or external configuration MUST apply the validation rules defined herein.
</rule_activation>

### Rules

- **R-ENV-001** MUST NOT: Application code MUST NOT directly access process.env or other unvalidated configuration sources; all access MUST go through validated configuration objects.

### Verify

```bash
# Detect direct process.env access outside of configuration modules
grep -r 'process\.env\.' --include='*.ts' --include='*.js' --exclude-dir=node_modules | grep -v 'z\.object\|zod\|schema' | wc -l

# Verify Zod imports are present in configuration modules
grep -r 'import.*zod' --include='*.ts' packages/ | wc -l

# Run configuration validation tests
npm test -- --grep 'configuration.*validation'
```

**Accept when:**
- All configuration modules use Zod schemas for validation with no direct process.env access in application logic
- CI pipeline includes tests that verify configuration validation behavior with invalid inputs
- Linting rules detect and flag direct environment variable access without validation
- ESLint custom rule successfully blocks direct process.env access outside of configuration modules
- Code review checklist confirms Zod schema validation for all new configuration parameters
- Static analysis tools report zero unvalidated external input usage

<enforcement>
Claude Code MUST NOT skip or defer verification. All configuration modules MUST be validated against R-ENV-001 before acceptance. Violations MUST be flagged during code review and CI/CD pipeline execution.
</enforcement>
