These rules are ALWAYS ACTIVE for all files matching public API client implementations, visualizer, playground, and blackboard component code.
</rule_activation>

### Rules

- **R-CACHE-001** MUST: Cached data MUST be versioned to handle schema changes and prevent stale data corruption.

### Verify

```bash
# Verify IndexedDB, localStorage, or sessionStorage usage patterns in cache/storage contexts
grep -r 'IndexedDB\|localStorage\|sessionStorage' packages/*/src --include='*.ts' --include='*.tsx' | grep -i 'cache\|storage\|provider'

# Verify cache TTL and expiration logic is implemented
grep -r 'cache.*TTL\|time.*to.*live\|expir' packages/*/src --include='*.ts' --include='*.tsx'

# Verify storage provider abstractions exist
grep -r 'class.*StorageProvider\|interface.*Cache' packages/*/src --include='*.ts' --include='*.tsx'
```

**Accept when:**
- All public API client implementations include a documented cache layer using browser storage APIs (IndexedDB, localStorage, or sessionStorage)
- Cache implementations include explicit TTL configuration and invalidation logic with versioning metadata
- Storage provider abstractions exist to decouple cache implementation from consumer code
- Cache keys follow consistent naming convention: 'api:version:endpoint:params'
- Cache metadata (timestamp, version, TTL) is stored alongside cached data

<enforcement>
Claude Code MUST verify all three bash commands pass before accepting public API client code. Violations must be flagged for revision. Architecture review is mandatory for new API client implementations. Exceptions require approval from both API Architecture Team and Security Team.
</enforcement>
