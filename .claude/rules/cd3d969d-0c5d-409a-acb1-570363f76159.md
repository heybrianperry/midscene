<rule_activation id="cd3d969d-0c5d-409a-acb1-570363f76159" title="Adopt Asynchronous Service Manager Pattern for UI Component Lifecycle: Service Managers Expose" applies_to="packages/*/src/**/*.ts,packages/*/src/**/*.tsx">
These rules are ALWAYS ACTIVE for UI components in visualizer, playground, and webdriver packages that manage asynchronous service initialization and lifecycle coordination.
</rule_activation>

### Rules

- **R-ASM-001** MAY: Service managers MAY expose lifecycle hooks for theme application and design system integration.

### Verify

```bash
# Detect ServiceManager pattern implementations
grep -r "class.*ServiceManager" packages/*/src --include="*.ts" --include="*.tsx"

# Verify async lifecycle methods
grep -r "async.*initialize\|async.*start\|async.*stop" packages/*/src/managers --include="*.ts"

# Check for lifecycle-related tests
npm run test -- --grep "ServiceManager" --reporter json | jq '.tests[] | select(.title | contains("lifecycle"))'
```

**Accept when:**
- All UI components with multiple async service dependencies use a ServiceManager or equivalent abstraction
- ServiceManager implementations consistently use Promise-based async/await patterns for lifecycle methods
- Code review checklist includes verification of ServiceManager pattern for complex UI components
- ServiceManager base interface or abstract class defines standard lifecycle methods (initialize, start, stop, cleanup)
- TypeScript types enforce proper service manager contracts
- Design system guidelines document the pattern with examples from visualizer, playground, and webdriver packages

<enforcement>
Claude Code MUST NOT skip or defer verification of ServiceManager pattern compliance in UI components with multiple async service dependencies. Violations MUST be flagged as CI build warnings and require code review feedback or technical debt tickets.
</enforcement>
