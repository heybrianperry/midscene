<rule_activation id="65898895-7f0e-4d78-a53a-8df837c73598" title="Adopt Service Client Integration Pattern for Backend Communication: Client Implementations Provide" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching backend client implementations, build scripts, and service integration code across the system.
</rule_activation>

### Rules

- **R-SCI-001** MAY: Client implementations MAY provide retry logic and error handling strategies appropriate to their execution context

### Verify

```bash
# Find backend client implementations
find . -name '*client*.ts' -o -name '*client*.js' | grep -E '(backend|service)' | head -10

# Verify exported client interfaces
grep -r 'export.*Client' --include='*.ts' --include='*.js' packages/ apps/ | grep -i backend

# Check build scripts for service coordination patterns
find apps/studio/scripts -name '*.mjs' -exec grep -l 'wait\|health\|ready' {} \;
```

**Accept when:**
- Backend client modules are found in dedicated files with clear naming patterns (e.g., backend-client.ts, service-client.ts)
- Build scripts demonstrate service coordination patterns with wait mechanisms or health checks
- Client implementations export typed interfaces or classes for backend service communication
- Retry logic and error handling are implemented appropriate to the execution context (browser, Node.js, Electron)
- Service boundaries are clearly defined and maintained between client-side and server-side logic

<enforcement>
Claude Code MUST verify that backend client implementations follow the Service Client Integration Pattern. Verification is mandatory before accepting code that integrates with backend services. Code review checks, CI pipeline integration tests, static analysis, and architecture reviews MUST all pass. Violations require refactoring or documented exceptions with tech lead approval.
</enforcement>
