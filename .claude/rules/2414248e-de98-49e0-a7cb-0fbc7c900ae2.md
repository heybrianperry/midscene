<rule_activation id="2414248e-de98-49e0-a7cb-0fbc7c900ae2" title="Implement Event Deduplication with In-Memory Cache Layer: Deduplication Window Cache" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files implementing event deduplication in high-throughput systems.
</rule_activation>

### Rules

- **R-DEDUP-001** SHOULD: The deduplication window (cache TTL) SHOULD be configured based on the expected duplicate arrival timeframe for the specific use case.

### Verify

```bash
# Verify cache implementations use Map or Set data structures
grep -r "new Map\|new Set" --include="*.ts" --include="*.js" | grep -i "cache\|dedup\|seen"

# Verify eviction logic is implemented (TTL-based or size-based)
grep -r "setTimeout\|setInterval" --include="*.ts" --include="*.js" | grep -i "clear\|evict\|cleanup"

# Verify deduplication tests exist and pass
npm test -- --grep "dedup\|duplicate" 2>&1 | grep -E "passing|failing"
```

**Accept when:**
- Event processing components use Map or Set data structures to track processed event identifiers
- Cache implementations include eviction logic (TTL-based or size-based) to prevent unbounded growth
- Unit tests verify that duplicate events are correctly identified and filtered by the cache layer
- Cache lookup times remain under 1ms at expected load
- Cache size limits are configured based on expected event rate and deduplication window
- Instrumentation tracks cache hit rate, size, and eviction frequency

<enforcement>
Claude Code MUST verify cache eviction policies in code review. MUST ensure unit tests demonstrate deduplication behavior with duplicate event scenarios. MUST validate performance tests confirm cache lookup times under 1ms. Violations require rejection of pull requests lacking proper cache eviction policies and production monitoring alerts when cache memory exceeds thresholds.
</enforcement>
