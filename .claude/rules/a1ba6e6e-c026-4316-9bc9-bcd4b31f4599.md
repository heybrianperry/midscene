<rule_activation id="a1ba6e6e-c026-4316-9bc9-bcd4b31f4599" title="Adopt Environment-Driven Configuration Management for Chrome Extension Packaging and Device Control: Configuration Management Implement" applies_to="**/*">
These rules are ACTIVE for all runtime environment configuration, Chrome extension packaging workflows, and device control systems that require environment-specific behavior adaptation.
</rule_activation>

### Rules

- **R-ENV-001** MAY: Configuration management MAY implement cascading configuration layers (defaults → environment-specific → runtime overrides) for maximum flexibility

### Verify

```bash
# Check for environment variable usage patterns
grep -r 'process.env' apps/chrome-extension/scripts/ packages/computer/src/ packages/computer/tests/ | grep -v node_modules

# Verify environment template exists
test -f .env.example && echo 'Environment template exists' || echo 'Missing .env.example'

# Scan for hardcoded secrets
grep -r 'API_KEY\|SECRET\|PASSWORD' --include='*.js' --include='*.ts' . | grep -v 'process.env' | grep -v node_modules || echo 'No hardcoded secrets found'
```

**Accept when:**
- All environment-specific values are loaded from process.env or configuration files, not hardcoded in source
- A .env.example file exists documenting all required environment variables
- No secrets or credentials are found hardcoded in source files (grep verification passes)
- Configuration validation runs at startup and provides clear error messages for missing/invalid values

<enforcement>
Claude Code MUST verify environment-driven configuration management compliance. Verification is mandatory before accepting changes to Chrome extension packaging, device control systems, or test automation helpers.
</enforcement>
