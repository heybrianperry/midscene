<rule_activation id="00611041-e108-47ba-9401-eeca86a74239" title="Adopt Asynchronous Service Manager Pattern for UI Component Lifecycle: Service Managers Handle" applies_to="packages/*/src/**/*.ts,packages/*/src/**/*.tsx">
These rules are ALWAYS ACTIVE for UI components in visualizer, playground, and webdriver packages that manage asynchronous service initialization and lifecycle operations.
</rule_activation>

### Rules

- **R-ASM-001** MUST: Service managers MUST handle Promise-based lifecycle operations (start, stop, cleanup) to ensure proper async/await patterns.

### Verify

```bash
# Detect ServiceManager pattern implementations
grep -r "class.*ServiceManager" packages/*/src --include="*.ts" --include="*.tsx"

# Verify async lifecycle methods
grep -r "async.*initialize\|async.*start\|async.*stop" packages/*/src/managers --include="*.ts"

# Check for lifecycle-related tests
npm run test -- --grep "ServiceManager" --reporter json | jq '.tests[] | select(.title | contains("lifecycle"))'
```

**Accept when:**
- All UI components with multiple async service dependencies use a ServiceManager or equivalent abstraction
- ServiceManager implementations consistently use Promise-based async/await patterns for lifecycle methods (initialize, start, stop, cleanup)
- Code review checklist includes verification of ServiceManager pattern for complex UI components
- TypeScript types enforce proper service manager contracts
- Components in visualizer, playground, and webdriver packages follow the established pattern

<enforcement>
Claude Code MUST NOT skip or defer verification of ServiceManager pattern compliance in UI components. Violations must be flagged during code review with requests for refactoring to the ServiceManager pattern.
</enforcement>
