<rule_activation id="88e9876e-1e59-43f3-aad1-1e3593a171ff" title="Standardize Unit Test Structure with Vitest for TypeScript Packages: Unit Tests Executable" applies_to="**/*.ts">
These rules are ALWAYS ACTIVE for all TypeScript packages within the monorepo. Unit tests must follow standardized structure and be executable via npm/yarn test commands in CI/CD pipelines.
</rule_activation>

### Rules

- **R-VITEST-001** MUST: Unit tests MUST be executable via npm/yarn test commands in CI/CD pipelines
- **R-VITEST-002** MUST: Unit tests MUST be located in tests/unit or tests/unit-test directories
- **R-VITEST-003** MUST: Unit test files MUST use .test.ts naming convention
- **R-VITEST-004** MUST: Each TypeScript package MUST have vitest.config.ts configured in package root
- **R-VITEST-005** MUST: package.json test script MUST run 'vitest run' for CI and 'vitest' for local development
- **R-VITEST-006** MUST: Vitest MUST be installed as a dev dependency in each package
- **R-VITEST-007** SHOULD: Coverage thresholds SHOULD be set to minimum 80% line coverage in vitest.config.ts
- **R-VITEST-008** SHOULD: Test files SHOULD import from 'vitest' for test utilities

### Verify

```bash
# Count unit test files in correct directory structure
find packages -name '*.test.ts' -type f | grep -E 'tests/(unit|unit-test)/' | wc -l

# Verify Vitest imports are present in test files
grep -r "from 'vitest'" packages/*/tests/unit*/*.test.ts | wc -l

# Verify vitest.config files exist in package roots
find packages -name 'vitest.config.ts' -o -name 'vitest.config.js' | wc -l
```

**Accept when:**
- All TypeScript packages contain unit tests in tests/unit or tests/unit-test directories with .test.ts extensions
- Vitest imports are present in test files and vitest.config files exist in package roots
- CI/CD pipeline successfully executes test commands and reports results for all packages
- Test coverage reports are generated and meet minimum threshold requirements (80% line coverage)
- package.json test scripts are configured for both CI ('vitest run') and local development ('vitest')
