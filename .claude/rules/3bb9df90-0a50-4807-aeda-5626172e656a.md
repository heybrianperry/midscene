<rule_activation id="3bb9df90-0a50-4807-aeda-5626172e656a" title="Adopt Playwright for E2E Testing of Frontend Rendering Models: Projects Extend Playwright" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching frontend rendering components, CLI tools with web UI, and integration tests requiring browser automation.
</rule_activation>

### Rules

- **R-PLAYWRIGHT-001** MAY: Projects MAY extend Playwright with custom fixtures or helpers specific to their rendering model requirements.

### Verify

```bash
# Check for Playwright test files
find . -name '*.spec.ts' -path '*/playwright/*' | wc -l | grep -v '^0$'

# Verify @playwright/test dependency
grep -r "@playwright/test" package.json packages/*/package.json

# Verify test scripts reference Playwright
grep -r "test.*playwright" package.json packages/*/package.json | grep -E '(test|e2e)'
```

**Accept when:**
- At least one Playwright test file exists in the project with .spec.ts extension
- Package.json includes @playwright/test as a dependency
- Test scripts reference Playwright for E2E testing execution
- E2E tests are organized in dedicated directories (e.g., tests/ai/web/playwright/)
- Test files use descriptive names indicating the rendering scenario (e.g., cache-functionality.spec.ts)

<enforcement>
Claude Code MUST verify Playwright E2E test presence for all frontend rendering components. Verification is mandatory before approving changes to web-based components, CLI tools with web UI, or cross-package integration tests. Violations require architectural review approval with documented justification.
</enforcement>
