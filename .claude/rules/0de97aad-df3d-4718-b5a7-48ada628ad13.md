<rule_activation id="0de97aad-df3d-4718-b5a7-48ada628ad13" title="Adopt Playwright for E2E Testing of Frontend Rendering Models: Tests Implement Fallback" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching frontend rendering components, CLI tools with web UI, and integration tests requiring browser automation.
</rule_activation>

### Rules

- **R-PLAYWRIGHT-001** MUST: Tests MUST implement fallback mechanisms (e.g., CDP fallback for screenshots) to handle browser API limitations.

### Verify

```bash
# Check for Playwright test files
find . -name '*.spec.ts' -path '*/playwright/*' | wc -l | grep -v '^0$'

# Verify @playwright/test dependency
grep -r "@playwright/test" package.json packages/*/package.json

# Verify test scripts reference Playwright
grep -r "test.*playwright" package.json packages/*/package.json | grep -E '(test|e2e)'
```

**Accept when:**
- At least one Playwright test file exists in the project with .spec.ts extension
- Package.json includes @playwright/test as a dependency
- Test scripts reference Playwright for E2E testing execution
- Tests for rendering features include fallback mechanisms (CDP fallback patterns demonstrated)
- E2E tests are organized in dedicated directories (e.g., tests/ai/web/playwright/)

<enforcement>
Claude Code MUST NOT skip or defer verification of Playwright E2E test presence and fallback mechanism implementation for frontend rendering components. Violations require architectural review approval with documented justification.
</enforcement>
