<rule_activation id="2af08f55-c22d-49b3-b95f-5dade760b560" title="Standardize Unit Test Structure with Vitest for TypeScript Packages: Packages Include Additional" applies_to="**/*">
These rules are ALWAYS ACTIVE for all TypeScript package development within the monorepo and apply to all unit test implementations in CI/CD pipelines.
</rule_activation>

### Rules

- **R-VITEST-001** MUST: Use Vitest as the standard testing framework for all TypeScript packages in the monorepo.
- **R-VITEST-002** MUST: Organize unit tests in `tests/unit` or `tests/unit-test` directories within each package.
- **R-VITEST-003** MUST: Name all unit test files with the `.test.ts` extension.
- **R-VITEST-004** MUST: Create or update `vitest.config.ts` in each package root with appropriate TypeScript and coverage settings.
- **R-VITEST-005** MUST: Configure `package.json` test script to run `vitest run` for CI and `vitest` for local development with watch mode.
- **R-VITEST-006** MUST: Set up coverage thresholds in `vitest.config.ts` to maintain minimum coverage requirements (e.g., 80% line coverage).
- **R-VITEST-007** MUST: Integrate test execution into CI/CD pipeline with appropriate failure conditions and reporting.
- **R-VITEST-008** MAY: Packages MAY include additional test types (integration, e2e) in separate directories with appropriate naming conventions.

### Verify

```bash
# Count unit test files in correct directory structure
find packages -name '*.test.ts' -type f | grep -E 'tests/(unit|unit-test)/' | wc -l

# Verify Vitest imports are present in test files
grep -r "from 'vitest'" packages/*/tests/unit*/*.test.ts | wc -l

# Count vitest.config files in package roots
find packages -name 'vitest.config.ts' -o -name 'vitest.config.js' | wc -l
```

**Accept when:**
- All TypeScript packages contain unit tests in `tests/unit` or `tests/unit-test` directories with `.test.ts` extensions
- Vitest imports are present in test files and `vitest.config` files exist in package roots
- CI/CD pipeline successfully executes test commands and reports results for all packages
- Test coverage reports are generated and meet minimum threshold requirements (80% line coverage)
- Package.json test scripts are configured for both CI (`vitest run`) and local development (`vitest` with watch mode)
