<rule_activation id="9220c3b7-aed8-42c9-a211-9e35ad927bee" title="Adopt Process Lifecycle Management Pattern for External Service Integration: Implementations Provide Configurable" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files that spawn or manage external processes, services, or integrations (XVFB, RDP backends, test servers, Playwright, browser automation, CLI tools managing background services, and integration adapters).
</rule_activation>

### Rules

- **R-PLM-001** MAY: Implementations MAY provide configurable timeout values for startup and shutdown phases based on service characteristics.
- **R-PLM-002** MUST: All files that spawn external processes MUST include corresponding termination/cleanup logic.
- **R-PLM-003** MUST: Integration modules MUST expose consistent start/stop APIs.
- **R-PLM-004** MUST: Create a shared base class or interface defining standard lifecycle methods (start, stop, healthCheck, getStatus) that all integrations should implement.
- **R-PLM-005** MUST: Implement timeout handling using Promise.race or similar patterns with configurable duration values stored in environment variables or configuration files.
- **R-PLM-006** MUST: Use process signal handlers (SIGTERM, SIGINT) to ensure cleanup code runs even on unexpected termination.
- **R-PLM-007** MUST: Add structured logging at key lifecycle events (starting, ready, stopping, stopped, error) with correlation IDs for tracing.
- **R-PLM-008** SHOULD: Consider implementing a process registry or manager class to track all spawned processes and ensure cleanup on application shutdown.

### Verify

```bash
# Check for spawn/exec/fork without cleanup
grep -r "spawn\|exec\|fork" --include="*.ts" --include="*.js" | grep -v "node_modules" | xargs -I {} sh -c 'echo "Checking: {}"; grep -l "terminate\|kill\|cleanup" "{}" || echo "WARNING: No cleanup found"'

# Find all process managers and verify cleanup exists
find . -type f \( -name "*.ts" -o -name "*.js" \) -not -path "*/node_modules/*" -exec grep -l "Process\|Service.*start\|spawn" {} \; | xargs grep -L "stop\|terminate\|cleanup" || echo "All process managers have cleanup"

# Verify lifecycle tests exist
npm test -- --grep "lifecycle|cleanup|shutdown" || echo "No lifecycle tests found"
```

**Accept when:**
- All files that spawn external processes include corresponding termination/cleanup logic
- Integration modules expose consistent start/stop APIs as verified by interface compliance checks
- Lifecycle tests exist for each external service integration covering startup, health check, and shutdown scenarios
- Timeout values are configurable with sensible defaults documented
- Process signal handlers (SIGTERM, SIGINT) are implemented for graceful shutdown
- Structured logging exists at key lifecycle events with correlation IDs

Claude Code MUST NOT skip or defer verification. Code review checklist MUST require verification of lifecycle management for any PR introducing external process integration. Automated linting rules MUST detect process spawning without corresponding cleanup handlers. CI pipeline tests MUST verify graceful shutdown behavior and resource cleanup. PRs MUST be blocked until lifecycle management is properly implemented.
</enforcement>
