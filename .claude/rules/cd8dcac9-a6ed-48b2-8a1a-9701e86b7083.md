<rule_activation id="cd8dcac9-a6ed-48b2-8a1a-9701e86b7083" title="Adopt React Component Export Pattern with Named Index Exports: Component Implementation Files" applies_to="packages/visualizer/**/*.tsx,packages/visualizer/**/*.ts,packages/recorder/**/*.tsx,packages/recorder/**/*.ts">
These rules are ALWAYS ACTIVE for all React component packages within the monorepo (packages/visualizer, packages/recorder) and apply to TypeScript/TSX component files that define reusable UI components.
</rule_activation>

### Rules

- **R-COMP-001** MUST: Component implementation files MUST be separate from the index.tsx export file to maintain clear separation between implementation and public API.

### Verify

```bash
# Count index files in component directories
find packages/*/src/component* -name 'index.tsx' -o -name 'index.ts' | wc -l

# Verify component imports use the index pattern
grep -r "export.*from.*component.*index" packages/visualizer packages/recorder

# Check for restricted direct imports bypassing index files
eslint --rule 'no-restricted-imports: [error, {patterns: ["**/component/*/*.tsx", "!**/component/*/index.tsx"]}]' packages/
```

**Accept when:**
- All component directories in packages/visualizer/src/component and packages/recorder/src/components contain an index.tsx or index.ts file
- Grep search confirms that component imports use the index pattern rather than direct file imports
- ESLint rules pass confirming no restricted direct imports to component implementation files

<enforcement>
Claude Code MUST NOT skip or defer verification. ESLint violations block PR merge in CI pipeline. Code review checklist requires index.tsx for new components. Automated bot comments on PRs suggesting the correct import pattern when violations are detected.
</enforcement>
