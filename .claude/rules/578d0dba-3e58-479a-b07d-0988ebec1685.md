<rule_activation id="578d0dba-3e58-479a-b07d-0988ebec1685" title="Standardize Vitest Configuration for Runtime Config Sources in CI/CD: Test Configuration Files" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in packages with test configurations, particularly packages/cli and packages/shared.
</rule_activation>

### Rules

- **R-VITEST-001** MUST: Test configuration files MUST be named 'vitest.config.ts' and placed at the package root level.

### Verify

```bash
# Verify vitest.config.ts files exist at package root level
find . -name 'vitest.config.ts' -type f | grep -E '(packages/[^/]+/vitest.config.ts)' || echo 'Missing vitest.config.ts files'

# Verify Vitest imports in configuration files
grep -r "import.*vitest" packages/*/vitest.config.ts | wc -l

# Validate test execution with standardized configuration
npm run test -- --reporter=json 2>&1 | jq '.success' || echo 'Test execution validation failed'
```

**Accept when:**
- All packages contain a vitest.config.ts file at their root level
- Test execution in CI/CD pipelines uses the standardized Vitest configurations
- Runtime configuration sources are explicitly defined and documented in each vitest.config.ts file

<enforcement>
Claude Code MUST NOT skip or defer verification. Automated CI/CD pipeline checks MUST validate presence of vitest.config.ts files. Pull requests MUST be blocked if test configuration does not meet standards. Violations result in CI/CD pipeline failure.
</enforcement>
