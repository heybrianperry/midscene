<rule_activation id="e17d6cf9-f0a9-4abd-b547-ad49891041d0" title="Standardize Test Organization in Dedicated Test Directories for CI/CD Integration: Test Directories Organized" applies_to="**/*">
These rules are ALWAYS ACTIVE for all TypeScript test files across all packages and applications in the monorepo.
</rule_activation>

### Rules

- **R-TEST-001** SHOULD: Test directories SHOULD be organized by test type (unit, integration, e2e) to support selective test execution in CI/CD pipelines.
- **R-TEST-002** MUST: All .test.ts files MUST be located within tests/ directories at the package or application root level.
- **R-TEST-003** MUST: Test files MUST use the .test.ts naming convention.
- **R-TEST-004** SHOULD: Each package and application SHOULD maintain its own tests/ directory structure.
- **R-TEST-005** MUST: Test files MUST NOT be co-located with source files in the same directory.

### Verify

```bash
# Verify no test files exist outside tests/ directories
find . -name '*.test.ts' -not -path '*/tests/*' -not -path '*/node_modules/*' | wc -l | grep -q '^0$'

# Count test files in expected locations
find packages/*/tests apps/*/tests -name '*.test.ts' 2>/dev/null | wc -l

# Verify test runner configurations reference tests/ directory pattern
grep -r 'testMatch\|testRegex' package.json tsconfig.json jest.config.* vitest.config.* 2>/dev/null
```

**Accept when:**
- All .test.ts files are located within tests/ directories (no test files found outside tests/ directories)
- Each package and application has its own tests/ directory at the package root level
- Test runner configurations reference the tests/ directory pattern for test discovery
- Test files follow the .test.ts naming convention consistently
- No .test.ts files are found co-located with source files in src/ or lib/ directories

<enforcement>
Claude Code MUST verify test file organization against these rules before approving changes to test structure or locations. Violations MUST be flagged and remediation guidance provided. CI/CD pipeline integration depends on consistent test discovery patterns.
</enforcement>
