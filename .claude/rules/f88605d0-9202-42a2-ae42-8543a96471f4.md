These rules are ALWAYS ACTIVE for all TypeScript packages within the monorepo. Unit tests must follow standardized structure and use Vitest as the testing framework.
</rule_activation>

### Rules

- **R-VITEST-001** MUST: All TypeScript packages MUST use Vitest as the unit testing framework.
- **R-VITEST-002** MUST: Unit tests MUST be located in `tests/unit` or `tests/unit-test` directories.
- **R-VITEST-003** MUST: Test files MUST use the `.test.ts` naming convention.
- **R-VITEST-004** MUST: Each TypeScript package MUST have a `vitest.config.ts` or `vitest.config.js` file in the package root.
- **R-VITEST-005** MUST: Package.json test script MUST run `vitest run` for CI and `vitest` for local development with watch mode.
- **R-VITEST-006** MUST: Coverage thresholds MUST be configured in vitest.config.ts with minimum 80% line coverage requirement.
- **R-VITEST-007** MUST: Vitest MUST be installed as a dev dependency in each package.
- **R-VITEST-008** SHOULD: Use detected pattern files (playground.test.ts, batch-runner.test.ts, server-session-manager.test.ts) as reference implementations.

### Verify

```bash
# Count test files in correct directory structure
find packages -name '*.test.ts' -type f | grep -E 'tests/(unit|unit-test)/' | wc -l

# Verify Vitest imports are present in test files
grep -r "from 'vitest'" packages/*/tests/unit*/*.test.ts | wc -l

# Verify vitest.config files exist in package roots
find packages -name 'vitest.config.ts' -o -name 'vitest.config.js' | wc -l
```

**Accept when:**
- All TypeScript packages contain unit tests in `tests/unit` or `tests/unit-test` directories with `.test.ts` extensions
- Vitest imports are present in test files and vitest.config files exist in package roots
- CI/CD pipeline successfully executes test commands and reports results for all packages
- Test coverage reports are generated and meet minimum 80% line coverage threshold requirements
- Package.json test scripts are configured for both CI (`vitest run`) and local development (`vitest`)
