These rules are ALWAYS ACTIVE for all files implementing integration patterns and their corresponding test files.
</rule_activation>

### Rules

- **R-UNIT-001** SHOULD: Test file naming SHOULD follow the convention of `<component-name>.test.<ext>` to clearly identify test files for integration patterns.

### Verify

```bash
# Count integration test files following naming convention
find . -path '*/tests/*' -name '*.test.*' -type f | grep -E '(integration|backend|client|smoke)' | wc -l

# Verify test files contain test definitions
grep -r "describe\|test\|it" --include='*.test.*' --include='*.spec.*' | grep -i 'integration\|backend\|client' | head -5

# List integration-related tests (command varies by project)
npm test -- --testPathPattern='(integration|backend|client)' --listTests 2>/dev/null || echo 'Test command varies by project'
```

**Accept when:**
- Integration pattern implementations include corresponding unit test files in `tests/` directories
- Unit tests execute successfully without requiring external service dependencies or infrastructure
- Test coverage for integration patterns meets or exceeds project-defined thresholds (typically 80%+)
- Test files follow the `<component-name>.test.<ext>` naming convention
- Test files are organized in consistent directory structures (e.g., `tests/unit-test/` or `tests/`)

<enforcement>
Claude Code MUST verify that integration pattern test files follow the naming convention `<component-name>.test.<ext>` and MUST NOT skip verification of test file organization and naming compliance.
</enforcement>
