<rule_activation id="17cb9a28-0c62-4c51-ac09-66b66cd5a5cf" title="Standardize Environment Variable Configuration Management Pattern: Environment Variable Access" applies_to="**/*">
These rules are ALWAYS ACTIVE for all configuration and environment management code across the codebase.
</rule_activation>

### Rules

- **R-ENV-001** MUST: All environment variable access MUST be centralized in dedicated configuration modules or files (e.g., common.ts, config.ts, env.ts)

### Verify

```bash
# Detect direct process.env access outside configuration modules
grep -r 'process\.env' --include='*.ts' --include='*.js' --exclude-dir=node_modules | grep -v 'common.ts\|config.ts\|env.ts' | wc -l

# Verify configuration modules exist and contain process.env access
find . -name 'common.ts' -o -name 'config.ts' -o -name 'env.ts' | xargs grep -l 'process\.env' | wc -l

# Check ESLint enforcement of no-process-env rule
npm run lint -- --rule 'no-process-env: error' 2>&1 | grep -c 'process.env'
```

**Accept when:**
- All direct process.env accesses are contained within designated configuration modules (common.ts, config.ts, env.ts)
- Each package with environment dependencies has a dedicated configuration module with typed exports
- Linting rules successfully detect and flag any direct process.env access outside configuration modules
- Configuration modules export typed constants or objects rather than exposing raw process.env
- Required vs. optional environment variables are documented in package README files

<enforcement>
Claude Code MUST verify that all environment variable access is centralized in dedicated configuration modules. Violations block CI pipeline and pull requests until refactored to use centralized configuration.
</enforcement>
