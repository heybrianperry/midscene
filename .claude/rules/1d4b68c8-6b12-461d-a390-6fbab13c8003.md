### Rules

- **R-DEDUP-001** SHOULD: Components SHOULD log or emit metrics when duplicate events are detected and filtered.

### Verify

```bash
# Verify cache implementations exist
grep -r "new Map\|new Set" --include="*.ts" --include="*.js" | grep -i "cache\|dedup\|seen"

# Verify eviction logic is present
grep -r "setTimeout\|setInterval" --include="*.ts" --include="*.js" | grep -i "clear\|evict\|cleanup"

# Verify deduplication tests exist
npm test -- --grep "dedup\|duplicate" 2>&1 | grep -E "passing|failing"
```

**Accept when:**
- Event processing components use Map or Set data structures to track processed event identifiers
- Cache implementations include eviction logic (TTL-based or size-based) to prevent unbounded growth
- Unit tests verify that duplicate events are correctly identified and filtered by the cache layer
- Components log or emit metrics when duplicates are detected and filtered
- Cache lookup times remain under 1ms at expected load

Claude Code MUST NOT skip or defer verification. Code review checklist MUST include verification of cache eviction policies. Unit tests MUST demonstrate deduplication behavior with duplicate event scenarios. Performance tests MUST validate cache lookup times. Pull requests without proper cache eviction policies MUST be rejected.
</enforcement>
