<rule_activation id="4ca8989f-462b-4f93-9355-bebbb8cbeee1" title="Standardize Test File Naming with .test.ts Extension for TypeScript Tests: Test Discovery Patterns" applies_to="**/*.ts">
These rules are ALWAYS ACTIVE for all TypeScript test files in the codebase. All test discovery, execution, and tooling configurations must recognize and process .test.ts files.
</rule_activation>

### Rules

- **R-TEST-001** SHOULD: Test discovery patterns in CI/CD configurations SHOULD use glob patterns like `**/*.test.ts` to automatically discover all test files.

### Verify

```bash
# Count all .test.ts files in the repository
find . -type f -name '*.test.ts' | wc -l

# Verify no alternative test naming conventions exist outside exceptions
find . -type f \( -name '*.spec.ts' -o -name '*_test.ts' \) -not -path '*/node_modules/*' | wc -l

# Verify test runner configurations include .test.ts pattern
grep -r 'testMatch.*\.test\.ts' --include='*.config.{js,ts}' .
```

**Accept when:**
- All TypeScript test files in the repository use `.test.ts` extension (first verify command returns count > 0, second command returns 0)
- Test runner configurations explicitly include `**/*.test.ts` pattern (third verify command finds matches)
- No test files with alternative extensions (`.spec.ts`, `_test.ts`) exist outside documented exceptions
- CI/CD pipeline successfully discovers and executes all tests using `.test.ts` glob pattern

<enforcement>
Claude Code MUST verify test file naming compliance before accepting TypeScript test files. Verification is mandatory and cannot be deferred.
</enforcement>
