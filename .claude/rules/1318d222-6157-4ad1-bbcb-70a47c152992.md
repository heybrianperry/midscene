<rule_activation id="1318d222-6157-4ad1-bbcb-70a47c152992" title="Standardize Environment Variable Configuration Management Pattern: Environment Variable Validation" applies_to="**/*">
These rules are ALWAYS ACTIVE for all configuration and environment management code across the codebase.
</rule_activation>

### Rules

- **R-ENV-001** MUST: Environment variable validation MUST occur at application initialization time, not at point of use.

### Verify

```bash
# Verify all direct process.env accesses are contained within designated configuration modules
grep -r 'process\.env' --include='*.ts' --include='*.js' --exclude-dir=node_modules | grep -v 'common.ts\|config.ts\|env.ts' | wc -l

# Verify each package has a dedicated configuration module with process.env access
find . -name 'common.ts' -o -name 'config.ts' -o -name 'env.ts' | xargs grep -l 'process\.env' | wc -l

# Verify linting rules detect direct process.env access outside configuration modules
npm run lint -- --rule 'no-process-env: error' 2>&1 | grep -c 'process.env'
```

**Accept when:**
- All direct process.env accesses are contained within designated configuration modules (common.ts, config.ts, env.ts)
- Each package with environment dependencies has a dedicated configuration module with typed exports
- Linting rules successfully detect and flag any direct process.env access outside configuration modules
- Environment variable validation occurs at application initialization time, not scattered throughout the codebase

<enforcement>
Claude Code MUST NOT skip or defer verification. All direct process.env access must be centralized in configuration modules and validated at initialization time.
</enforcement>
