### Rules

- **R-INT-001** SHOULD: Backend client integrations SHOULD include smoke tests that validate basic startup and initialization behavior.

### Verify

```bash
# Count integration test files
find . -path '*/tests/*' -name '*.test.*' -type f | grep -E '(integration|backend|client|smoke)' | wc -l

# Search for test patterns in integration-related files
grep -r "describe\|test\|it" --include='*.test.*' --include='*.spec.*' | grep -i 'integration\|backend\|client' | head -5

# List integration tests (command varies by project)
npm test -- --testPathPattern='(integration|backend|client)' --listTests 2>/dev/null || echo 'Test command varies by project'
```

**Accept when:**
- Integration pattern implementations include corresponding unit test files in tests/ directories
- Unit tests execute successfully without requiring external service dependencies or infrastructure
- Test coverage for integration patterns meets or exceeds project-defined thresholds (typically 80%+)
- Test naming conventions clearly identify the integration component being tested (e.g., backend-client.test.ts, startup-smoke.test.mjs)
- Smoke tests for critical integration paths validate basic startup and initialization behavior

Claude Code MUST verify that backend client integrations include unit tests with smoke test coverage before approving integration pattern implementations. Verification is mandatory and MUST NOT be skipped or deferred.
