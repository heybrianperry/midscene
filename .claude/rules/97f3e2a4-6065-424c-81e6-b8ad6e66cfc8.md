<rule_activation id="97f3e2a4-6065-424c-81e6-b8ad6e66cfc8" title="Adopt IndexedDB as Client-Side Cache Layer for Logging and State Persistence: Applications Implement Synchronization" applies_to="**/*">
These rules are ALWAYS ACTIVE for all client-side applications, Chrome extensions, browser-based tools, and Progressive Web Applications requiring persistent storage for logging and state persistence.
</rule_activation>

### Rules

- **R-IDB-001** MAY: Applications MAY implement synchronization mechanisms to periodically upload cached logs to remote servers when connectivity is available.

### Verify

```bash
# Detect IndexedDB usage patterns in client-side code
grep -r "indexedDB\|IndexedDB\|IDBDatabase" apps/ packages/ --include="*.ts" --include="*.tsx" --include="*.js"

# Verify database operations and transactions
grep -r "openDatabase\|createObjectStore\|transaction" apps/ packages/ --include="*.ts" --include="*.tsx"

# Run tests for IndexedDB, caching, and logging storage
npm test -- --grep "IndexedDB|cache.*persist|logging.*storage"
```

**Accept when:**
- All client-side logging and caching implementations use IndexedDB utilities with proper async/await error handling
- IndexedDB implementations include cleanup policies and quota management mechanisms
- Code review confirms no synchronous localStorage usage for large data or logging purposes in browser extension contexts
- Centralized IndexedDB utility module (e.g., indexedDB.ts) encapsulates database initialization, schema versioning, and CRUD operations
- Structured logging schemas include indexes on timestamp, severity level, and component name
- Automatic cleanup mechanisms are implemented using periodic background tasks with configurable retention periods
- Database versioning (onupgradeneeded) is used for schema migrations

<enforcement>
Claude Code MUST NOT skip or defer verification. All IndexedDB implementations MUST be validated against the verify commands and accept-when criteria before approval. Violations using localStorage for large data or logging MUST be flagged for review. Repeated violations REQUIRE architecture team review and justification.
</enforcement>
