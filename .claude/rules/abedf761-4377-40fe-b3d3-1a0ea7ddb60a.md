These rules are ALWAYS ACTIVE for all data access patterns involving periodic state synchronization, event optimization, and keepalive mechanisms across the codebase. Applies to browser extension background scripts, real-time streaming components, event optimization utilities, and client-side modules performing periodic health checks or state synchronization.
</rule_activation>

### Rules

- **R-POLL-001** MAY: Implementations MAY use exponential backoff or adaptive intervals when connection failures or errors are detected.

### Verify

```bash
# Count setInterval/setTimeout calls without corresponding cleanup
grep -r 'setInterval\|setTimeout' --include='*.ts' --include='*.js' | grep -v 'clearInterval\|clearTimeout' | wc -l

# Verify setInterval calls have corresponding clearInterval in cleanup paths
grep -r 'setInterval' --include='*.ts' --include='*.tsx' -A 10 | grep -c 'clearInterval'

# Check for polling/interval/keepalive tests with cleanup verification
npm run test -- --grep 'polling\|interval\|keepalive' --reporter json | jq '.tests[] | select(.title | contains("cleanup"))'
```

**Accept when:**
- All setInterval and setTimeout calls have corresponding clearInterval/clearTimeout in cleanup paths (component unmount, error handlers, connection close)
- Polling intervals are defined as named constants or configuration values rather than inline magic numbers
- Unit tests exist for polling mechanisms that verify cleanup behavior using fake timers (jest.useFakeTimers or sinon.useFakeTimers)
- Exponential backoff or adaptive intervals are implemented with documented retry logic and maximum backoff caps
- Browser timer throttling is accounted for with chrome.alarms API or visibility change detection in extension contexts

<enforcement>
Claude Code MUST verify all polling and interval implementations against these rules. Violations in setInterval/setTimeout cleanup, magic number intervals, or missing test coverage MUST be flagged. Verification is mandatory before accepting polling-related code changes.
</enforcement>
