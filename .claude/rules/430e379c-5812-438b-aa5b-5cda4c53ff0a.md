<rule_activation id="430e379c-5812-438b-aa5b-5cda4c53ff0a" title="Standardize Logging Configuration with Environment-Based Debug Control: Debug Logging Disabled" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime environments and configuration management implementations within the system, covering all packages (playground, computer, web-integration) and deployment contexts.
</rule_activation>

### Rules

- **R-LOG-001** MUST: Debug logging MUST be disabled by default in production environments unless explicitly enabled via configuration.
- **R-LOG-002** MUST: Use environment variables (DEBUG, LOG_LEVEL, VERBOSE) for logging configuration across all runtime components in packages: playground, computer, web-integration.
- **R-LOG-003** MUST: Implement initialization code that reads environment variables early in the application lifecycle before any logging occurs.
- **R-LOG-004** SHOULD: Use a consistent logging library across packages that natively supports environment variable configuration (e.g., debug, winston, pino).
- **R-LOG-005** SHOULD: Document all supported logging environment variables in each package's README with examples for common scenarios.
- **R-LOG-006** SHOULD: Consider using a shared configuration module that standardizes environment variable parsing and provides defaults.
- **R-LOG-007** SHOULD: Add integration tests that verify logging behavior under different environment variable configurations.
- **R-LOG-008** MAY: Implement runtime API endpoints for dynamic logging level changes without restart as a complementary enhancement for long-running services.

### Verify

```bash
# Check for environment variable-based logging configuration
grep -r 'process\.env\.(DEBUG|LOG_LEVEL|VERBOSE)' packages/*/src --include='*.ts' --include='*.js'

# Count console.log and logger calls without environment variable guards
grep -r 'console\.log\|logger\.' packages/*/src --include='*.ts' | grep -v 'if.*DEBUG\|if.*process\.env' | wc -l

# Verify debug logging can be enabled via environment variable
docker run --rm -e DEBUG=* <image> npm test 2>&1 | grep -q 'debug:' && echo 'Debug logging enabled'
```

**Accept when:**
- All packages in scope (playground, computer, web-integration) demonstrate environment variable-based logging configuration in their initialization code
- Documentation exists for each package describing supported logging environment variables and their effects
- Integration tests verify that logging behavior changes appropriately when environment variables are set vs. unset
- No hard-coded logging levels exist in production code paths that cannot be overridden by environment configuration
- Environment variable naming conventions are consistent across packages (e.g., DEBUG, LOG_LEVEL, VERBOSE)
- Log sanitization is implemented for sensitive fields to prevent exposure of secrets or PII in debug mode

<enforcement>
Claude Code MUST NOT skip or defer verification of these logging configuration rules. All R-LOG rules MUST be verified before accepting changes to logging initialization, configuration, or environment variable handling. Violations MUST trigger CI pipeline warnings and code review feedback requiring environment-based configuration for new logging implementations.
</enforcement>
