<rule_activation id="5c36fa1b-f8c7-45d1-a29b-08be6c6cc1a4" title="Adopt Playwright for E2E Testing of Frontend Rendering Models: Tests Validate Both" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in packages with frontend components requiring browser rendering validation.
</rule_activation>

### Rules

- **R-PW-001** SHOULD: Tests SHOULD validate both positive rendering scenarios and edge cases (narrow inputs, fallback mechanisms).

### Verify

```bash
# Verify Playwright test files exist
find . -name '*.spec.ts' -path '*/playwright/*' | wc -l | grep -v '^0$'

# Verify @playwright/test dependency
grep -r "@playwright/test" package.json packages/*/package.json

# Verify test scripts reference Playwright
grep -r "test.*playwright" package.json packages/*/package.json | grep -E '(test|e2e)'
```

**Accept when:**
- At least one Playwright test file exists in the project with .spec.ts extension
- Package.json includes @playwright/test as a dependency
- Test scripts reference Playwright for E2E testing execution
- E2E tests cover both positive rendering scenarios and edge cases (fallback mechanisms, narrow inputs)
- Tests are organized in dedicated directories (e.g., tests/ai/web/playwright/)
- Test files use descriptive names indicating the rendering scenario being validated

<enforcement>
Claude Code MUST verify Playwright E2E test presence and coverage for all frontend components. Violations require architectural review approval with documented justification. Temporary exceptions must include a remediation plan with timeline.
</enforcement>
