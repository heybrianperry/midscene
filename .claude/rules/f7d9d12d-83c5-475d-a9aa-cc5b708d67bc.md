<rule_activation id="f7d9d12d-83c5-475d-a9aa-cc5b708d67bc" title="Adopt Asynchronous Service Manager Pattern for UI Component Lifecycle: Components Requiring Platform" applies_to="**/*">
These rules are ALWAYS ACTIVE for UI components in visualizer, playground, and webdriver packages that require platform-specific services (export, rendering, webdriver) and asynchronous lifecycle management.
</rule_activation>

### Rules

- **R-ASYNC-001** SHOULD: Components requiring platform-specific services (export, rendering, webdriver) SHOULD delegate service orchestration to manager classes rather than inline initialization.
- **R-ASYNC-002** SHOULD: Create a base ServiceManager interface or abstract class that defines standard lifecycle methods (initialize, start, stop, cleanup).
- **R-ASYNC-003** SHOULD: Ensure all ServiceManager implementations return Promises and use async/await consistently.
- **R-ASYNC-004** SHOULD: Add TypeScript types to enforce proper service manager contracts and prevent misuse.
- **R-ASYNC-005** SHOULD: Document the pattern in design system guidelines with examples from visualizer, playground, and webdriver packages.
- **R-ASYNC-006** MUST NOT: Use inline async initialization within components without manager abstraction for components with multiple async service dependencies.
- **R-ASYNC-007** MUST NOT: Tightly couple service orchestration to specific UI framework lifecycle hooks (useEffect, mounted) for reusable components.

### Verify

```bash
# Detect ServiceManager pattern usage across UI packages
grep -r "class.*ServiceManager" packages/*/src --include="*.ts" --include="*.tsx"

# Verify async lifecycle methods in manager implementations
grep -r "async.*initialize\|async.*start\|async.*stop" packages/*/src/managers --include="*.ts"

# Check for ServiceManager-related tests with lifecycle focus
npm run test -- --grep "ServiceManager" --reporter json | jq '.tests[] | select(.title | contains("lifecycle"))'
```

**Accept when:**
- All UI components with multiple async service dependencies use a ServiceManager or equivalent abstraction
- ServiceManager implementations consistently use Promise-based async/await patterns for lifecycle methods (initialize, start, stop, cleanup)
- Code review checklist includes verification of ServiceManager pattern for complex UI components
- TypeScript types are enforced on all ServiceManager implementations
- Design system documentation includes ServiceManager pattern examples

<enforcement>
Claude Code MUST verify ServiceManager pattern compliance during code review. Violations MUST be flagged as CI build warnings or code review feedback requesting refactoring to ServiceManager pattern. Exceptions require documented rationale and architecture team approval.
</enforcement>
