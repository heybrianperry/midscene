<rule_activation id="24bf7976-6f3b-4a07-be11-6687869b6dcc" title="Adopt Process Lifecycle Management Pattern for External Service Integration: Process Spawning Include" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files that spawn or manage external processes, including XVFB, RDP backends, test servers, Playwright, and other service integrations.
</rule_activation>

### Rules

- **R-PLM-001** MUST: Process spawning MUST include health check mechanisms to verify service readiness before proceeding with dependent operations.

### Verify

```bash
# Check for spawn/exec/fork without corresponding cleanup
grep -r "spawn\|exec\|fork" --include="*.ts" --include="*.js" | grep -v "node_modules" | xargs -I {} sh -c 'echo "Checking: {}"; grep -l "terminate\|kill\|cleanup" "{}" || echo "WARNING: No cleanup found"'

# Find all process managers and verify they have cleanup logic
find . -type f \( -name "*.ts" -o -name "*.js" \) -not -path "*/node_modules/*" -exec grep -l "Process\|Service.*start\|spawn" {} \; | xargs grep -L "stop\|terminate\|cleanup" || echo "All process managers have cleanup"

# Verify lifecycle tests exist
npm test -- --grep "lifecycle|cleanup|shutdown" || echo "No lifecycle tests found"
```

**Accept when:**
- All files that spawn external processes include corresponding termination/cleanup logic
- Integration modules expose consistent start/stop APIs as verified by interface compliance checks
- Lifecycle tests exist for each external service integration covering startup, health check, and shutdown scenarios
- Health check mechanisms are implemented before dependent operations proceed
- Process signal handlers (SIGTERM, SIGINT) are configured for graceful shutdown
- Structured logging exists at key lifecycle events (starting, ready, stopping, stopped, error)

<enforcement>
Claude Code MUST NOT skip or defer verification of process lifecycle management. All external process integrations MUST include health checks and cleanup logic before code is accepted. Violations block PR merge until remediated.
</enforcement>
