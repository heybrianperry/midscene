<rule_activation id="72ec96d5-aa3b-4f5f-a301-e07b3b95eed4" title="Adopt Event-Driven Data Access with Buffering and Retry Mechanisms: Components Performing Network" applies_to="**/*">
These rules are ALWAYS ACTIVE for all components performing network-based data access, event handling, AI model connectivity, real-time data streaming, and MCP tool integrations.
</rule_activation>

### Rules

- **R-EVDA-001** MUST: Components performing network-based data access MUST implement retry logic with exponential backoff for transient failures.

### Scope

**In scope:**
- All network-based data access operations (HTTP, WebSocket, streaming protocols)
- Event handling systems in browser extensions and web integrations
- AI model connectivity and API interactions
- Real-time data streaming components (MJPEG, video, telemetry)
- MCP tool integrations and external service communications

**Out of scope:**
- Synchronous, in-memory data access within a single process
- Database query patterns using connection pools (covered by separate ADRs)
- File system I/O operations
- Static configuration loading

**Exceptions:**
- EXC-001: Real-time systems with strict latency requirements where buffering would violate SLA constraints
- EXC-002: Prototype or experimental features explicitly marked as non-production

### Verify

```bash
# Count retry and buffering patterns in codebase
grep -r "retry\|backoff\|buffer" --include="*.ts" --include="*.js" packages/ apps/ | grep -v node_modules | wc -l

# Count event-driven patterns
grep -r "EventEmitter\|Observable\|Subject" --include="*.ts" packages/ apps/ | grep -v node_modules | wc -l

# Run retry/buffer/reconnect tests
npm test -- --grep "retry|buffer|reconnect" 2>&1 | grep -E "passing|failing"
```

**Accept when:**
- All network-based data access components implement retry logic with exponential backoff (verified by code review)
- Event-driven components include buffering mechanisms with defined overflow policies (verified by implementation inspection)
- Test suites include scenarios for connection failures, retries, and buffer overflow conditions (verified by test execution)
- Buffer depth metrics and retry rates are monitored in production dashboards
- Maximum buffer sizes are implemented with overflow policies (drop oldest, drop newest, or circuit break)
- Exponential backoff with jitter is used to prevent retry storms
- Circuit breakers are implemented for failing services
- Sequence numbers or timestamps are used to maintain data ordering in concurrent event processing

<enforcement>
Claude Code MUST NOT skip or defer verification of retry logic, buffering mechanisms, and exponential backoff implementation in network-based data access components. All violations MUST be flagged in PR comments before merge. Architecture review escalation is required for components that cannot implement standard patterns.
</enforcement>
