<rule_activation id="4ffdff7e-c395-4586-b004-bf3316cf73c7" title="Standardize Public API Export Patterns for External Integration: Internal Implementation Details" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in packages intended for external consumption (visualizer, cli, playground, computer), particularly public-facing functions, classes, types, and interfaces exported from package entry points.
</rule_activation>

### Rules

- **R-API-001** MUST NOT: Internal implementation details MUST NOT be exposed through public API surfaces without explicit documentation marking them as unstable.
- **R-API-002** MUST: All packages intended for external use have an index.ts or equivalent public API entry point with explicit exports.
- **R-API-003** MUST: Public API exports include TypeScript type definitions and JSDoc documentation for all exported members.
- **R-API-004** SHOULD: Use TypeScript's @public, @internal, @experimental, and @deprecated JSDoc tags to clearly communicate stability levels.
- **R-API-005** SHOULD: Leverage API Extractor or similar tools to generate API reports and detect unintended breaking changes in CI/CD pipelines.
- **R-API-006** SHOULD: Use the 'exports' field in package.json to enforce module boundaries and prevent deep imports into internal directories.
- **R-API-007** MAY: Establish clear deprecation policies with migration guides and use adapter patterns to bridge old and new implementations during transition periods.

### Verify

```bash
# Count explicit exports in package entry points
grep -r "export.*from" packages/*/src/index.ts | wc -l

# Verify all index files have exports
find packages -name 'index.ts' -type f | xargs grep -L 'export' && echo 'Missing exports found' || echo 'All index files have exports'

# Validate API surface with API Extractor
npx api-extractor run --local --verbose 2>&1 | grep -i 'error\|warning' || echo 'API surface validated'
```

**Accept when:**
- All packages intended for external use have an index.ts or equivalent public API entry point with explicit exports
- API extractor or equivalent tooling runs successfully in CI without detecting unintended breaking changes
- Public API exports include TypeScript type definitions and JSDoc documentation for all exported members
- TypeScript compiler strict mode passes without errors on exported APIs
- No internal implementation details are exposed in public API surfaces without @internal or @experimental tags
