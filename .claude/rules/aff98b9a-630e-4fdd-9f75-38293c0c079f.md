<rule_activation id="aff98b9a-630e-4fdd-9f75-38293c0c079f" title="Adopt Process Lifecycle Management Pattern for External Service Integration: Integration Modules Expose" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files that spawn or manage external processes, services, or integrations (XVFB, RDP backend, test servers, Playwright, browser automation, CLI tools managing background services).
</rule_activation>

### Rules

- **R-PLCM-001** SHOULD: Integration modules SHOULD expose consistent APIs for start, stop, and status operations across different service types.
- **R-PLCM-002** MUST: All files that spawn external processes MUST include corresponding termination/cleanup logic.
- **R-PLCM-003** MUST: Create a shared base class or interface defining standard lifecycle methods (start, stop, healthCheck, getStatus) that all integrations implement.
- **R-PLCM-004** MUST: Implement timeout handling using Promise.race or similar patterns with configurable duration values stored in environment variables or configuration files.
- **R-PLCM-005** MUST: Use process signal handlers (SIGTERM, SIGINT) to ensure cleanup code runs even on unexpected termination.
- **R-PLCM-006** MUST: Add structured logging at key lifecycle events (starting, ready, stopping, stopped, error) with correlation IDs for tracing.
- **R-PLCM-007** SHOULD: Consider implementing a process registry or manager class to track all spawned processes and ensure cleanup on application shutdown.

### Verify

```bash
# Check for process spawning without cleanup
grep -r "spawn\|exec\|fork" --include="*.ts" --include="*.js" | grep -v "node_modules" | xargs -I {} sh -c 'echo "Checking: {}"; grep -l "terminate\|kill\|cleanup" "{}" || echo "WARNING: No cleanup found"'

# Find all process managers and verify cleanup exists
find . -type f \( -name "*.ts" -o -name "*.js" \) -not -path "*/node_modules/*" -exec grep -l "Process\|Service.*start\|spawn" {} \; | xargs grep -L "stop\|terminate\|cleanup" || echo "All process managers have cleanup"

# Verify lifecycle tests exist
npm test -- --grep "lifecycle|cleanup|shutdown" || echo "No lifecycle tests found"
```

**Accept when:**
- All files that spawn external processes include corresponding termination/cleanup logic
- Integration modules expose consistent start/stop APIs as verified by interface compliance checks
- Lifecycle tests exist for each external service integration covering startup, health check, and shutdown scenarios
- Process signal handlers (SIGTERM, SIGINT) are implemented for graceful shutdown
- Structured logging with correlation IDs is present at key lifecycle events

<enforcement>
Claude Code MUST NOT skip or defer verification. Code review checklist MUST require verification of lifecycle management for any PR introducing external process integration. Automated linting rules MUST detect process spawning without corresponding cleanup handlers. CI pipeline tests MUST verify graceful shutdown behavior and resource cleanup. PRs MUST be blocked until lifecycle management is properly implemented.
</enforcement>
