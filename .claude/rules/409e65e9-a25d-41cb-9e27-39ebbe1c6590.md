These rules are ALWAYS ACTIVE for all files matching backend client implementations, build scripts, and service coordination code.

### Rules

- **R-SCI-001** MUST: Build and packaging scripts MUST use consistent integration patterns when coordinating with backend services.

### Verify

```bash
# Find backend client implementations
find . -name '*client*.ts' -o -name '*client*.js' | grep -E '(backend|service)' | head -10

# Verify backend client exports
grep -r 'export.*Client' --include='*.ts' --include='*.js' packages/ apps/ | grep -i backend

# Find build scripts with service coordination patterns
find apps/studio/scripts -name '*.mjs' -exec grep -l 'wait\|health\|ready' {} \;
```

**Accept when:**
- Backend client modules are found in dedicated files with clear naming patterns (e.g., backend-client.ts, service-client.ts)
- Build scripts demonstrate service coordination patterns with wait mechanisms or health checks
- Client implementations export typed interfaces or classes for backend service communication
- Service boundaries are clearly defined and enforced through dedicated client modules
- Type safety is maintained in client-backend communication via TypeScript interfaces

<enforcement>
Claude Code MUST verify all three bash commands pass before accepting changes to backend client implementations, build scripts, or service coordination code. Violations require refactoring to comply with dedicated client module patterns and service boundary enforcement.
</enforcement>
