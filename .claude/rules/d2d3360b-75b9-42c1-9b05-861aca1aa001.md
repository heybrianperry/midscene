These rules are ALWAYS ACTIVE for all files matching `**/*`. Integration pattern implementations across the codebase must include unit tests that validate integration contracts and behavior.

### Rules

- **R-INTPAT-001** MUST: All integration pattern implementations MUST include unit tests that validate the integration contract and behavior.

### Verify

```bash
# Count integration pattern test files
find . -path '*/tests/*' -name '*.test.*' -type f | grep -E '(integration|backend|client|smoke)' | wc -l

# Verify test descriptions reference integration patterns
grep -r "describe\|test\|it" --include='*.test.*' --include='*.spec.*' | grep -i 'integration\|backend\|client' | head -5

# List integration-related tests
npm test -- --testPathPattern='(integration|backend|client)' --listTests 2>/dev/null || echo 'Test command varies by project'
```

**Accept when:**
- Integration pattern implementations include corresponding unit test files in tests/ directories
- Unit tests execute successfully without requiring external service dependencies or infrastructure
- Test coverage for integration patterns meets or exceeds project-defined thresholds (typically 80%+)
- Test naming conventions clearly identify the integration component being tested (e.g., backend-client.test.ts, startup-smoke.test.mjs)
- Integration contract being tested is documented in test descriptions

<enforcement>
Claude Code MUST NOT skip or defer verification. All integration pattern implementations require unit tests before acceptance. CI/CD pipeline verification is mandatory and violations must be addressed before merge.
</enforcement>
