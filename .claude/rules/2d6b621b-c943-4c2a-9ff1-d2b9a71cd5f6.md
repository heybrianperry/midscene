<rule_activation id="2d6b621b-c943-4c2a-9ff1-d2b9a71cd5f6" title="Standardize Test Organization in Dedicated Test Directories for CI/CD Integration: Packages Include Additional" applies_to="**/*.test.ts">
These rules are ALWAYS ACTIVE for all TypeScript test files across all packages and applications in the monorepo.
</rule_activation>

### Rules

- **R-TEST-001** MUST: Place all test files in dedicated `tests/` directories at the package or application root level, not co-located with source files.
- **R-TEST-002** MUST: Name all test files with the `.test.ts` extension (e.g., `component.test.ts`, `service.test.ts`).
- **R-TEST-003** MUST: Organize test files within `tests/` using subdirectories for test categories: `tests/unit/`, `tests/integration/`, `tests/e2e/`.
- **R-TEST-004** MAY: Include additional test categories beyond unit/integration (e.g., `tests/stress/`, `tests/performance/`) in appropriately named subdirectories.
- **R-TEST-005** MUST: Ensure each package in `packages/*/` and each application in `apps/*/` maintains its own `tests/` directory at the package root level.
- **R-TEST-006** MUST: Configure test runners (Jest, Vitest, Mocha) to discover tests using glob patterns like `tests/**/*.test.ts`.
- **R-TEST-007** MUST: Exclude `tests/` directories from production builds via `tsconfig.json` or build tool configuration.

### Verify

```bash
# Verify no test files exist outside tests/ directories
find . -name '*.test.ts' -not -path '*/tests/*' -not -path '*/node_modules/*' | wc -l | grep -q '^0$'

# Count test files in expected locations
find packages/*/tests apps/*/tests -name '*.test.ts' 2>/dev/null | wc -l

# Verify test runner configurations reference tests/ directory pattern
grep -r 'testMatch\|testRegex' package.json tsconfig.json jest.config.* vitest.config.* 2>/dev/null
```

**Accept when:**
- All `.test.ts` files are located within `tests/` directories (no test files found outside `tests/` directories)
- Each package and application has its own `tests/` directory at the package root level
- Test runner configurations reference the `tests/` directory pattern for test discovery
- Test files follow the `.test.ts` naming convention consistently
- Subdirectories within `tests/` follow the `unit/`, `integration/`, `e2e/` convention or other clearly named categories
