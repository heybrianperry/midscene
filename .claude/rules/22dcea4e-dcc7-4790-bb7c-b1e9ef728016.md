<rule_activation id="22dcea4e-dcc7-4790-bb7c-b1e9ef728016" title="Implement Event Deduplication with In-Memory Cache Layer: Implementations Use Lru" applies_to="**/*">
These rules are ALWAYS ACTIVE for event processing pipelines, real-time data stream processors, and keepalive mechanisms that handle external or user-generated events where duplicate processing would cause incorrect state or side effects.
</rule_activation>

### Rules

- **R-DEDUP-001** MAY: Implementations MAY use LRU (Least Recently Used) or other eviction strategies based on access patterns.

### Verify

```bash
# Verify cache implementations use Map or Set data structures
grep -r "new Map\|new Set" --include="*.ts" --include="*.js" | grep -i "cache\|dedup\|seen"

# Verify eviction logic is present (TTL-based or size-based)
grep -r "setTimeout\|setInterval" --include="*.ts" --include="*.js" | grep -i "clear\|evict\|cleanup"

# Verify deduplication tests exist
npm test -- --grep "dedup\|duplicate" 2>&1 | grep -E "passing|failing"
```

**Accept when:**
- Event processing components use Map or Set data structures to track processed event identifiers
- Cache implementations include eviction logic (TTL-based or size-based) to prevent unbounded growth
- Unit tests verify that duplicate events are correctly identified and filtered by the cache layer
- Cache lookup times remain under 1ms at expected load
- Cache size limits are configured based on expected event rate and deduplication window

<enforcement>
Claude Code MUST verify cache eviction policies in code review. MUST reject pull requests without proper cache eviction policies. MUST validate deduplication behavior with duplicate event scenarios in unit tests. Verification is mandatory before accepting event processing implementations.
</enforcement>
