<rule_activation id="9f52fa4b-3213-4606-8f5c-1f311dc6a85c" title="Adopt IndexedDB as Client-Side Cache Layer for Logging and State Persistence: Client Side Applications" applies_to="**/*">
These rules are ALWAYS ACTIVE for all client-side applications including Chrome extensions, browser-based tools, and Progressive Web Applications requiring persistent logging and state management.
</rule_activation>

### Rules

- **R-IDB-001** MUST: Client-side applications MUST use IndexedDB as the primary cache layer for persistent logging and state management in Chrome extensions, Progressive Web Applications (PWAs), and browser-based state management layers.

### Scope

**In scope:**
- Chrome extensions and browser extensions
- Progressive Web Applications (PWAs)
- Client-side logging and observability infrastructure
- Browser-based state management and caching layers
- Offline-first application architectures

**Out of scope:**
- Server-side logging infrastructure
- Native mobile applications (iOS/Android)
- Node.js backend services
- Real-time streaming analytics pipelines
- Applications with strict GDPR requirements prohibiting client-side data storage

**Exceptions:**
- EXC-001: Application operates in environments where IndexedDB is not available (legacy browsers, restricted contexts)
- EXC-002: Regulatory or security requirements explicitly prohibit client-side persistent storage

### Verify

```bash
# Search for IndexedDB usage patterns
grep -r "indexedDB\|IndexedDB\|IDBDatabase" apps/ packages/ --include="*.ts" --include="*.tsx" --include="*.js"

# Search for database operations
grep -r "openDatabase\|createObjectStore\|transaction" apps/ packages/ --include="*.ts" --include="*.tsx"

# Run tests for IndexedDB, caching, and persistence
npm test -- --grep "IndexedDB|cache.*persist|logging.*storage"
```

**Accept when:**
- All client-side logging and caching implementations use IndexedDB utilities with proper async/await error handling
- IndexedDB implementations include cleanup policies and quota management mechanisms
- Code review confirms no synchronous localStorage usage for large data or logging purposes in browser extension contexts
- IndexedDB utility module (e.g., indexedDB.ts) encapsulates database initialization, schema versioning, and common CRUD operations
- Structured logging schemas include indexes on timestamp, severity level, and component name
- Automatic cleanup mechanisms are implemented using periodic background tasks
- Database versioning (onupgradeneeded) is used for schema migrations
