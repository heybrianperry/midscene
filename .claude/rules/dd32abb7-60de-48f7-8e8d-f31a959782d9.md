<rule_activation id="dd32abb7-60de-48f7-8e8d-f31a959782d9" title="Adopt Vitest as Standard Test Framework for CI/CD Pipeline: Tests Properly Handle" applies_to="**/*.test.ts">
These rules are ALWAYS ACTIVE for all test files in the monorepo. Vitest is the standard test framework for handling asynchronous operations and concurrent test execution across all packages.
</rule_activation>

### Rules

- **R-VITEST-001** MUST: Tests MUST properly handle asynchronous operations using async/await patterns supported by Vitest.
- **R-VITEST-002** MUST: All test files MUST import test utilities (describe, test, expect) from the 'vitest' package.
- **R-VITEST-003** MUST: Test files MUST follow the .test.ts naming convention and be organized in tests/ directories.
- **R-VITEST-004** MUST: A vitest.config.ts or vite.config.ts file with test configuration MUST exist in the project.
- **R-VITEST-005** SHOULD: Tests SHOULD be organized using tests/unit and tests/integration directory structures to clearly separate test types.
- **R-VITEST-006** SHOULD: Shared test setup files (e.g., tests/setup.ts) SHOULD be maintained to configure Vitest globals, mocks, and environment variables for all packages.
- **R-VITEST-007** SHOULD: Tests SHOULD follow proper isolation guidelines and use setup/teardown hooks to enable concurrent execution.

### Verify

```bash
# Verify Vitest imports in test files
grep -r "from 'vitest'" --include='*.test.ts' || grep -r 'from "vitest"' --include='*.test.ts'

# Verify Vitest configuration exists
find . -name 'vitest.config.*' -o -name 'vite.config.*' | xargs grep -l 'test'

# Verify test file patterns
grep -r "describe\|test\|it\|expect" --include='*.test.ts' | head -5

# Verify CI/CD pipeline executes Vitest
grep -r "vitest run" --include='*.yml' --include='*.yaml' --include='*.json'
```

**Accept when:**
- All test files import test utilities (describe, test, expect) from 'vitest' package
- A vitest.config.ts or vite.config.ts file exists with test configuration
- Test files follow the .test.ts naming convention and are organized in tests/ directories
- CI/CD pipeline executes 'vitest run' command and fails builds on test failures
- Tests properly handle asynchronous operations using async/await patterns

Claude Code MUST NOT skip or defer verification. All test files MUST comply with R-VITEST-001 through R-VITEST-007. Violations block CI/CD pipeline merges and require code review corrections or documented exceptions with architecture review board approval.
