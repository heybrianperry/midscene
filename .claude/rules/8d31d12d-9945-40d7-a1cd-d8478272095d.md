<rule_activation id="8d31d12d-9945-40d7-a1cd-d8478272095d" title="Standardize Public API Export Patterns for External Integration: Public Exports Maintain" applies_to="**/*">
These rules are ALWAYS ACTIVE for all packages intended for external consumption (visualizer, cli, playground, computer) and their public-facing exports.
</rule_activation>

### Rules

- **R-API-001** MUST: Public API exports MUST maintain semantic versioning and backward compatibility guarantees across minor versions.

### Verify

```bash
# Count explicit exports in package entry points
grep -r "export.*from" packages/*/src/index.ts | wc -l

# Verify all index files have exports
find packages -name 'index.ts' -type f | xargs grep -L 'export' && echo 'Missing exports found' || echo 'All index files have exports'

# Validate API surface with API Extractor
npx api-extractor run --local --verbose 2>&1 | grep -i 'error\|warning' || echo 'API surface validated'
```

**Accept when:**
- All packages intended for external use have an index.ts or equivalent public API entry point with explicit exports
- API extractor or equivalent tooling runs successfully in CI without detecting unintended breaking changes
- Public API exports include TypeScript type definitions and JSDoc documentation for all exported members
- All exported members are tagged with @public, @internal, @experimental, or @deprecated JSDoc tags
- No breaking changes are introduced without a corresponding major version bump

<enforcement>
Claude Code MUST NOT skip or defer verification. All public API changes MUST pass API Extractor validation and code review checklist before merge. Violations trigger CI pipeline failure and require architecture team approval for exceptions.
</enforcement>
