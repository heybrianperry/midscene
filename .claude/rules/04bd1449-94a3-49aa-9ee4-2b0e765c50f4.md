These rules are ALWAYS ACTIVE for all files matching external API integrations across the codebase, including visualizer, prompt utilities, and AI model action layers.
</rule_activation>

### Rules

- **R-API-001** MAY: Teams MAY implement caching layers for external API responses when data freshness requirements allow.
- **R-API-002** MUST: All HTTP/REST API calls to external third-party services use the standardized API client wrapper.
- **R-API-003** MUST: All GraphQL queries to external providers use the standardized API client wrapper.
- **R-API-004** MUST: All WebSocket connections to external real-time services use the standardized API client wrapper.
- **R-API-005** MUST: All SDK-based integrations with external platforms (AWS, GCP, Azure, OpenAI, etc.) use the standardized API client wrapper.
- **R-API-006** MUST NOT: Direct usage of HTTP libraries (fetch, axios, node-fetch, http.get, http.post) outside of the centralized API client wrapper.
- **R-API-007** SHOULD: Implement standard interfaces for authentication (OAuth2, API keys, JWT), request/response transformation, and error handling.
- **R-API-008** SHOULD: Use TypeScript interfaces or JSON Schema to define expected API response structures for validation.
- **R-API-009** SHOULD: Integrate external API calls with existing observability stack (logging, metrics, tracing).

### Scope

**In scope:**
- All HTTP/REST API calls to external third-party services
- GraphQL queries to external providers
- WebSocket connections to external real-time services
- SDK-based integrations with external platforms (AWS, GCP, Azure, OpenAI, etc.)

**Out of scope:**
- Internal microservice-to-microservice communication within the same deployment
- Database access patterns (covered by separate data layer ADRs)
- File system or local resource access
- In-process function calls or library usage

**Exceptions:**
- EXC-001: Legacy integrations that predate this ADR and are scheduled for deprecation within 6 months
- EXC-002: Proof-of-concept or experimental features in isolated feature branches

### Verify

```bash
# Count direct HTTP library usage outside standardized wrapper
grep -r 'fetch\|axios\|http\.get\|http\.post' packages/ --include='*.ts' --include='*.js' | grep -v '@company/external-api-client' | wc -l

# Run integration tests for external API clients
npm run test:integration -- --grep 'external API'

# Lint for restricted HTTP library imports
eslint packages/ --rule 'no-restricted-imports: [error, {patterns: [axios, node-fetch]}]' --ext .ts,.js
```

**Accept when:**
- All new external API integrations use the standardized client wrapper (verified by code review checklist)
- Integration tests pass for all external API clients with mocked responses covering success, error, and timeout scenarios
- No direct usage of HTTP libraries (fetch, axios) outside of the centralized API client wrapper (verified by linting rules)
- grep command returns 0 non-compliant HTTP library usages
- eslint linting rules pass with no violations
