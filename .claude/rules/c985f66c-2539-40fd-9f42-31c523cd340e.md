<rule_activation id="c985f66c-2539-40fd-9f42-31c523cd340e" title="Adopt Event-Driven Keepalive Pattern for Long-Running Connections: Keepalive Implementations Use" applies_to="**/*">
These rules are ALWAYS ACTIVE for all data access patterns involving persistent connections, streaming protocols, or long-lived client-server interactions where connection stability is critical.
</rule_activation>

### Rules

- **R-KEEPALIVE-001** SHOULD: Keepalive implementations SHOULD use configurable intervals to adapt to different network conditions and application requirements

### Verify

```bash
# Detect keepalive implementations
grep -r "keepalive\|keepAlive" --include="*.ts" --include="*.js" | grep -v node_modules

# Find interval-based connection patterns (ping, pong, heartbeat)
grep -r "setInterval\|setTimeout" --include="*.ts" --include="*.js" | grep -E "(ping|pong|heartbeat|keepalive)" | grep -v node_modules

# Verify browser lifecycle event handling
grep -r "addEventListener.*visibility\|addEventListener.*suspend" --include="*.ts" --include="*.js" | grep -v node_modules
```

**Accept when:**
- All long-running connection implementations include explicit keepalive mechanisms with configurable intervals
- Event-driven data access patterns demonstrate event optimization through debouncing, throttling, or batching
- Connection management code handles browser lifecycle events (visibility changes, suspend/resume) appropriately
- Verification commands identify consistent patterns across connection management modules
- WebSocket connections, SSE, streaming protocols (MJPEG), browser extensions, and real-time synchronization mechanisms all implement keepalive patterns

<enforcement>
Claude Code MUST NOT skip or defer verification. All long-running connection implementations MUST be reviewed against these rules before approval. Violations require code review feedback and architecture review escalation. Exceptions require technical lead approval and quarterly review.
</enforcement>
