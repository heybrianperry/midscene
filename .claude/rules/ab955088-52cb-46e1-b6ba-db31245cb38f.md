These rules are ALWAYS ACTIVE for all files matching backend client implementations, build scripts, and service integration code across the system.
</rule_activation>

### Rules

- **R-SCI-001** SHOULD: Client implementations SHOULD provide type-safe interfaces for backend service communication.

### Verify

```bash
# Find backend client implementations
find . -name '*client*.ts' -o -name '*client*.js' | grep -E '(backend|service)' | head -10

# Verify exported client interfaces
grep -r 'export.*Client' --include='*.ts' --include='*.js' packages/ apps/ | grep -i backend

# Check build scripts for service coordination patterns
find apps/studio/scripts -name '*.mjs' -exec grep -l 'wait\|health\|ready' {} \;
```

**Accept when:**
- Backend client modules are found in dedicated files with clear naming patterns (e.g., backend-client.ts, service-client.ts)
- Build scripts demonstrate service coordination patterns with wait mechanisms or health checks
- Client implementations export typed interfaces or classes for backend service communication
- Type safety is enforced through TypeScript interfaces or type definitions in client-backend communication
- Service boundaries are clearly defined and maintained across different execution contexts (browser, Node.js, Electron)

<enforcement>
Claude Code MUST verify all backend client implementations follow type-safe interface patterns. Code review processes MUST check for proper client module organization. CI pipeline MUST run integration tests across different execution contexts. Static analysis tools MUST verify type safety. Violations flagged for refactoring before merge. Exceptions require tech lead approval and documentation.
</enforcement>
