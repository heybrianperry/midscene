<rule_activation id="48515676-aff7-496d-957e-130e9b06539c" title="Standardize Browser and Platform API Abstraction Layers for External Integration: Abstraction Modules Handle" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. Platform API abstraction layers MUST be used consistently across all packages integrating with external APIs (Chrome Extension APIs, browser DOM APIs, Node.js platform APIs, native system APIs, and third-party platform SDKs).
</rule_activation>

### Rules

- **R-ABSTRACTION-001** MUST: Abstraction modules MUST handle platform availability checks and provide graceful degradation or clear error messages when APIs are unavailable.

### Verify

```bash
# Check for direct references to platform globals outside abstraction modules
grep -r 'window\.chrome\|global\.chrome' --include='*.ts' --include='*.tsx' --exclude-dir=node_modules --exclude='**/utils/chrome.ts' . | grep -v 'typeof.*chrome' | wc -l | awk '{if ($1 > 0) exit 1}'

# Check for direct process API usage outside abstraction modules
grep -r 'process\.' --include='*.ts' --exclude-dir=node_modules --exclude='**/utils/*.ts' --exclude='**/*.config.*' . | wc -l | awk '{if ($1 > 10) exit 1}'

# Verify at least one platform API abstraction module exists
find . -name 'chrome.ts' -o -name 'platform.ts' -o -name '*-api.ts' | grep utils | wc -l | awk '{if ($1 < 1) exit 1}'
```

**Accept when:**
- No direct references to platform globals (window.chrome, process, etc.) exist outside of designated abstraction utility modules
- At least one platform API abstraction module exists in packages that integrate with external APIs
- All platform API abstractions provide TypeScript type definitions and handle availability checks

<enforcement>
Claude Code MUST NOT skip or defer verification. All three verification commands MUST pass before accepting code changes that introduce or modify platform API usage.
</enforcement>
