<rule_activation id="fca67f24-aba0-4ed5-a80e-2753bd5adb48" title="Adopt Service Client Integration Pattern for Backend Communication: Service Client Modules" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching backend client implementations, build scripts, and service integration code across the system.
</rule_activation>

### Rules

- **R-SCI-001** SHOULD: Service client modules SHOULD be organized by service domain (e.g., rdp, electron-build) to maintain clear architectural boundaries.
- **R-SCI-002** SHOULD: Create dedicated client modules in appropriate package locations (e.g., packages/computer/src/rdp/backend-client.ts) with clear naming conventions.
- **R-SCI-003** SHOULD: Use TypeScript interfaces or type definitions to enforce type safety in client-backend communication.
- **R-SCI-004** SHOULD: For build scripts, implement wait-for-service patterns with configurable timeouts and health check endpoints to ensure backend availability.
- **R-SCI-005** SHOULD: Document the execution context requirements and limitations for each client implementation.
- **R-SCI-006** MUST: Implement contract testing between clients and services to prevent client implementations from drifting from backend service contracts.
- **R-SCI-007** MUST: Implement robust timeout and retry logic in build scripts that interact with backend services.
- **R-SCI-008** MUST: Establish comprehensive integration testing across all target environments (browser, Node.js, Electron).

### Verify

```bash
# Find backend client modules with clear naming patterns
find . -name '*client*.ts' -o -name '*client*.js' | grep -E '(backend|service)' | head -10

# Verify backend client exports
grep -r 'export.*Client' --include='*.ts' --include='*.js' packages/ apps/ | grep -i backend

# Find build scripts with service coordination patterns
find apps/studio/scripts -name '*.mjs' -exec grep -l 'wait\|health\|ready' {} \;
```

**Accept when:**
- Backend client modules are found in dedicated files with clear naming patterns (e.g., backend-client.ts, service-client.ts)
- Build scripts demonstrate service coordination patterns with wait mechanisms or health checks
- Client implementations export typed interfaces or classes for backend service communication
- TypeScript type safety is enforced in client-backend communication
- Service boundaries are clearly defined and maintained across different execution contexts

<enforcement>
Clause Code MUST verify all rules through code review, CI pipeline integration tests across execution contexts, static analysis for type safety, and architecture review sessions. Violations must be flagged for refactoring. Exceptions require tech lead approval, documentation, and quarterly review.
</enforcement>
