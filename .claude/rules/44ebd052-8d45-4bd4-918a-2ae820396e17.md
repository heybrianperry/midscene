<rule_activation id="44ebd052-8d45-4bd4-918a-2ae820396e17" title="Standardize Vitest Configuration for Runtime Config Sources in CI/CD: Individual Packages Extend" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching test configurations, Vitest config files, and CI/CD pipeline definitions across packages/cli/tests, packages/shared/tests, and package root level vitest.config.ts files.
</rule_activation>

### Rules

- **R-VITEST-001** MAY: Individual packages MAY extend the base Vitest configuration with package-specific settings when necessary.

### Verify

```bash
# Verify vitest.config.ts files exist at package root level
find . -name 'vitest.config.ts' -type f | grep -E '(packages/[^/]+/vitest.config.ts)' || echo 'Missing vitest.config.ts files'

# Verify Vitest imports in configuration files
grep -r "import.*vitest" packages/*/vitest.config.ts | wc -l

# Validate test execution with standardized configuration
npm run test -- --reporter=json 2>&1 | jq '.success' || echo 'Test execution validation failed'
```

**Accept when:**
- All packages contain a vitest.config.ts file at their root level
- Test execution in CI/CD pipelines uses the standardized Vitest configurations
- Runtime configuration sources are explicitly defined and documented in each vitest.config.ts file

<enforcement>
Claude Code MUST verify all three conditions above before accepting Vitest configuration changes. Verification is mandatory and MUST NOT be skipped or deferred. CI/CD pipeline checks MUST validate presence of vitest.config.ts files, and pull requests MUST be blocked if test configuration does not meet standards.
</enforcement>
