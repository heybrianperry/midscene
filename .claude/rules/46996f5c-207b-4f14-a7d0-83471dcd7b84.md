<rule_activation id="46996f5c-207b-4f14-a7d0-83471dcd7b84" title="Standardize Core Library Module Imports and Dependencies: Packages Export Commonly" applies_to="**/*">
These rules are ALWAYS ACTIVE for all TypeScript, JavaScript, C++, and related files in packages/visualizer, packages/recorder, packages/cli, apps/*, and packages/computer/native/.
</rule_activation>

### Rules

- **R-20-001** MAY: Packages MAY re-export commonly used core library functions through barrel files (index.ts/tsx) to simplify imports.
- **R-20-006** SHOULD: Maintain consistent import ordering across all TypeScript/JavaScript files.

### Verify

```bash
# Verify ESLint import ordering rules pass
eslint --ext .ts,.tsx,.js,.mjs --rule 'import/order: error' packages/ apps/

# Check import patterns across visualizer and recorder packages
grep -r "^import.*from" packages/visualizer/src packages/recorder/src apps/ | head -20

# Verify all package.json files declare core library dependencies explicitly
find packages/ apps/ -name 'package.json' -exec jq '.dependencies, .devDependencies' {} \;

# Detect circular dependencies
madge --circular --extensions ts,tsx,js packages/ apps/
```

**Accept when:**
- ESLint import ordering rules pass for all TypeScript/JavaScript files with no violations
- No circular dependencies detected by madge or similar dependency analysis tools
- All package.json files declare core library dependencies explicitly with no implicit peer dependencies
- Code review checklist includes verification of import ordering and dependency declarations
- Barrel files (index.ts) in shared packages simplify common import patterns while maintaining explicit dependencies

Claude Code MUST NOT skip or defer verification. CI build fails if ESLint import ordering rules are violated. Pull requests are blocked if circular dependencies are detected. Automated comments on PRs highlight import order violations with suggested fixes.
