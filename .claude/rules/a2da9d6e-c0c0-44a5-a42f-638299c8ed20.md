<rule_activation id="a2da9d6e-c0c0-44a5-a42f-638299c8ed20" title="Adopt IndexedDB as Client-Side Cache Layer for Logging and State Persistence: Indexeddb Implementations Handle" applies_to="**/*">
These rules are ALWAYS ACTIVE for all client-side applications, Chrome extensions, browser-based tools, and Progressive Web Applications requiring persistent storage for logging and state persistence.
</rule_activation>

### Rules

- **R-IDB-001** MUST: IndexedDB implementations MUST handle asynchronous operations using Promises or async/await patterns to prevent blocking the main thread.

### Verify

```bash
# Search for IndexedDB usage patterns
grep -r "indexedDB\|IndexedDB\|IDBDatabase" apps/ packages/ --include="*.ts" --include="*.tsx" --include="*.js"

# Search for database operations
grep -r "openDatabase\|createObjectStore\|transaction" apps/ packages/ --include="*.ts" --include="*.tsx"

# Run tests for IndexedDB, caching, and logging storage
npm test -- --grep "IndexedDB|cache.*persist|logging.*storage"
```

**Accept when:**
- All client-side logging and caching implementations use IndexedDB utilities with proper async/await error handling
- IndexedDB implementations include cleanup policies and quota management mechanisms
- Code review confirms no synchronous localStorage usage for large data or logging purposes in browser extension contexts
- No blocking synchronous operations detected in IndexedDB transaction handlers
- Asynchronous error handling is implemented for all database operations

<enforcement>
Claude Code MUST NOT skip or defer verification. All IndexedDB implementations MUST be validated against R-IDB-001 before acceptance. Violations must be flagged for architecture team review.
</enforcement>
