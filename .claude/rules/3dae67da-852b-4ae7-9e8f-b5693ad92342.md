### Rules

- **R-SCI-001** MUST: Integration patterns MUST support multiple execution contexts including browser environments, Node.js scripts, and Electron processes.

### Verify

```bash
# Find backend client implementations
find . -name '*client*.ts' -o -name '*client*.js' | grep -E '(backend|service)' | head -10

# Verify exported client interfaces
grep -r 'export.*Client' --include='*.ts' --include='*.js' packages/ apps/ | grep -i backend

# Find build scripts with service coordination patterns
find apps/studio/scripts -name '*.mjs' -exec grep -l 'wait\|health\|ready' {} \;
```

**Accept when:**
- Backend client modules are found in dedicated files with clear naming patterns (e.g., backend-client.ts, service-client.ts)
- Build scripts demonstrate service coordination patterns with wait mechanisms or health checks
- Client implementations export typed interfaces or classes for backend service communication
- Integration tests pass across different execution contexts (browser, Node.js, Electron)
- Type safety is enforced in client-backend communication via TypeScript interfaces

<enforcement>
Claude Code MUST NOT skip or defer verification of service client integration patterns. All backend communication MUST flow through dedicated client modules with proper type safety and execution context support. Violations require refactoring before merge.
