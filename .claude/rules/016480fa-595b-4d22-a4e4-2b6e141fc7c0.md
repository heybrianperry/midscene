<rule_activation id="016480fa-595b-4d22-a4e4-2b6e141fc7c0" title="Enforce Environment Variable Validation with Zod Schema for Runtime Configuration: Configuration Modules Export" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime configuration and environment variable handling in the codebase. All modules that consume environment variables or external configuration MUST apply the validation rules defined herein.
</rule_activation>

### Rules

- **R-ENV-001** MAY: Configuration modules MAY export both the Zod schema and the validated configuration object for reuse and testing.

### Verify

```bash
# Detect direct process.env access without validation
grep -r 'process\.env\.' --include='*.ts' --include='*.js' --exclude-dir=node_modules | grep -v 'z\.object\|zod\|schema' | wc -l

# Count Zod imports in configuration modules
grep -r 'import.*zod' --include='*.ts' packages/ | wc -l

# Run configuration validation tests
npm test -- --grep 'configuration.*validation'
```

**Accept when:**
- All configuration modules use Zod schemas for validation with no direct process.env access in application logic
- CI pipeline includes tests that verify configuration validation behavior with invalid inputs
- Linting rules detect and flag direct environment variable access without validation
- Configuration modules export both the schema type and the validated config object
- Error messages clearly indicate which environment variable failed validation and the expected format

<enforcement>
Claude Code MUST verify that all environment variable consumption uses Zod schema validation. Direct process.env access in application logic is a violation. Configuration modules MUST export validated configuration objects with their schemas. Verification is mandatory before accepting configuration-related code.
</enforcement>
