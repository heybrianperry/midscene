### Rules

- **R-VITEST-001** MUST: CI/CD pipelines MUST execute all test suites and fail builds on test failures.
- **R-VITEST-002** MUST: All test files import test utilities (describe, test, expect) from 'vitest' package.
- **R-VITEST-003** MUST: Test files follow the .test.ts naming convention and are organized in tests/ directories.
- **R-VITEST-004** MUST: A vitest.config.ts or vite.config.ts file with test configuration must exist.
- **R-VITEST-005** SHOULD: Use Vitest's workspace feature for monorepo configurations to enable per-package test configuration while maintaining shared defaults.
- **R-VITEST-006** SHOULD: Maintain shared test setup files (e.g., tests/setup.ts) that configure Vitest globals, mocks, and environment variables for all packages.
- **R-VITEST-007** SHOULD: Organize tests using tests/unit and tests/integration directory structure to clearly separate test types.
- **R-VITEST-008** SHOULD: Establish test isolation guidelines and use proper setup/teardown hooks for concurrent test execution.

### Verify

```bash
# Verify Vitest imports in test files
grep -r "from 'vitest'" --include='*.test.ts' || grep -r 'from "vitest"' --include='*.test.ts'

# Verify Vitest configuration exists
find . -name 'vitest.config.*' -o -name 'vite.config.*' | xargs grep -l 'test'

# Verify test file patterns
grep -r "describe\|test\|it\|expect" --include='*.test.ts' | head -5

# Verify CI/CD pipeline executes tests
grep -r "vitest run" --include='*.yml' --include='*.yaml' --include='*.json'
```

**Accept when:**
- All test files import test utilities (describe, test, expect) from 'vitest' package
- A vitest.config.ts or vite.config.ts file exists with test configuration
- Test files follow the .test.ts naming convention and are organized in tests/ directories
- CI/CD pipeline executes 'vitest run' command and fails builds on test failures
- New tests follow Vitest patterns and naming conventions
- Test file naming conventions and import patterns are enforced by linting rules
