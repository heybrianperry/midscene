<rule_activation id="e8230156-f972-44f9-86c7-fc518cc3a6c4" title="Standardize Public API Export Patterns for External Integration: Breaking Changes Public" applies_to="**/*">
These rules are ALWAYS ACTIVE for all packages intended for external consumption (visualizer, cli, playground, computer) and their public-facing APIs.
</rule_activation>

### Rules

- **R-API-001** SHOULD: Breaking changes to public APIs SHOULD be deprecated for at least one major version before removal, with clear migration paths documented.

### Verify

```bash
# Count explicit exports in package entry points
grep -r "export.*from" packages/*/src/index.ts | wc -l

# Verify all index files have exports
find packages -name 'index.ts' -type f | xargs grep -L 'export' && echo 'Missing exports found' || echo 'All index files have exports'

# Validate API surface with API Extractor
npx api-extractor run --local --verbose 2>&1 | grep -i 'error\|warning' || echo 'API surface validated'
```

**Accept when:**
- All packages intended for external use have an index.ts or equivalent public API entry point with explicit exports
- API extractor or equivalent tooling runs successfully in CI without detecting unintended breaking changes
- Public API exports include TypeScript type definitions and JSDoc documentation for all exported members
- Breaking changes are accompanied by deprecation notices and migration guides
- Public APIs are marked with @public, @internal, @experimental, or @deprecated JSDoc tags

<enforcement>
Claude Code MUST verify public API exports and deprecation patterns before approving changes to packages intended for external consumption. Verification via API Extractor and export audits is mandatory. Breaking changes without proper deprecation periods require architecture team approval.
</enforcement>
