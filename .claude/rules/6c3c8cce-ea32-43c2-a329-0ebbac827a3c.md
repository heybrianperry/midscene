<rule_activation id="6c3c8cce-ea32-43c2-a329-0ebbac827a3c" title="Standardize Public API Export Patterns for External Integration: Public Modules Follow" applies_to="**/*">
These rules are ALWAYS ACTIVE for all packages intended for external consumption (visualizer, cli, playground, computer) and their public-facing APIs.
</rule_activation>

### Rules

- **R-API-001** SHOULD: Public API modules SHOULD follow a consistent naming convention (e.g., index.ts, public-api.ts, or exports.ts) across all packages.
- **R-API-002** MUST: Use TypeScript 'export' statements in index.ts files at package roots to create explicit public API surfaces.
- **R-API-003** SHOULD: Leverage API Extractor or similar tools to generate API reports and detect unintended breaking changes in CI/CD pipelines.
- **R-API-004** SHOULD: Consider using the 'exports' field in package.json to enforce module boundaries and prevent deep imports into internal directories.
- **R-API-005** SHOULD: Document public APIs using JSDoc with @public, @internal, @experimental, and @deprecated tags to clearly communicate stability levels.
- **R-API-006** MUST: All packages intended for external use have an index.ts or equivalent public API entry point with explicit exports.
- **R-API-007** MUST: Public API exports include TypeScript type definitions and JSDoc documentation for all exported members.
- **R-API-008** MUST: API extractor or equivalent tooling runs successfully in CI without detecting unintended breaking changes.

### Verify

```bash
# Count explicit exports in package entry points
grep -r "export.*from" packages/*/src/index.ts | wc -l

# Find index files missing exports
find packages -name 'index.ts' -type f | xargs grep -L 'export' && echo 'Missing exports found' || echo 'All index files have exports'

# Validate API surface with API Extractor
npx api-extractor run --local --verbose 2>&1 | grep -i 'error\|warning' || echo 'API surface validated'
```

**Accept when:**
- All packages intended for external use have an index.ts or equivalent public API entry point with explicit exports
- API extractor or equivalent tooling runs successfully in CI without detecting unintended breaking changes
- Public API exports include TypeScript type definitions and JSDoc documentation for all exported members

<enforcement>
Claude Code MUST NOT skip or defer verification. Automated CI checks using API Extractor or similar tools MUST detect API surface changes. Code review MUST verify public API boundaries. TypeScript compiler strict mode MUST enforce type safety on exported APIs. CI pipeline MUST fail if API surface changes are detected without corresponding version bump. Pull requests exposing internal APIs without @internal tags MUST be flagged for revision.
</enforcement>
