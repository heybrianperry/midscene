<rule_activation id="275ea413-9ed7-4a75-a43b-366115dbfc70" title="Implement Event Deduplication with In-Memory Cache Layer: Each Cached Entry" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files implementing event deduplication with in-memory cache layers in high-throughput event processing systems.
</rule_activation>

### Rules

- **R-DEDUP-001** MUST: Each cached entry MUST have a unique identifier (event ID, message hash, or composite key) that can be used for deduplication lookups.

### Verify

```bash
# Verify cache data structures are in use
grep -r "new Map\|new Set" --include="*.ts" --include="*.js" | grep -i "cache\|dedup\|seen"

# Verify eviction logic is implemented
grep -r "setTimeout\|setInterval" --include="*.ts" --include="*.js" | grep -i "clear\|evict\|cleanup"

# Verify deduplication tests exist
npm test -- --grep "dedup\|duplicate" 2>&1 | grep -E "passing|failing"
```

**Accept when:**
- Event processing components use Map or Set data structures to track processed event identifiers
- Cache implementations include eviction logic (TTL-based or size-based) to prevent unbounded growth
- Unit tests verify that duplicate events are correctly identified and filtered by the cache layer
- Cache lookup times remain under 1ms at expected load (validated by performance tests)
- Cache size limits are configured based on expected event rate and deduplication window
- Instrumentation tracks cache hit rate, size, and eviction frequency
