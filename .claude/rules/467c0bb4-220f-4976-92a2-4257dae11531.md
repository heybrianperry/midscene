<rule_activation id="467c0bb4-220f-4976-92a2-4257dae11531" title="Adopt Event-Driven Async Integration Pattern for Backend Communication: Event Driven Components" applies_to="**/*">
These rules are ALWAYS ACTIVE for all integration components communicating with backend services, RDP clients, and browser automation frameworks.
</rule_activation>

### Rules

- **R-EVDA-001** SHOULD: Event-driven components SHOULD provide typed event interfaces for type safety and developer experience.
- **R-EVDA-002** MUST: Use async/await syntax consistently rather than mixing with raw Promises for better readability.
- **R-EVDA-003** MUST: Implement proper error boundaries with try-catch blocks around all await expressions.
- **R-EVDA-004** MUST: For event-driven components, document all emitted events with TypeScript interfaces or type definitions.
- **R-EVDA-005** SHOULD: Consider using libraries like 'p-queue' or 'p-limit' for controlling concurrency levels in batch operations.
- **R-EVDA-006** SHOULD: Add timeout wrappers around external service calls to prevent indefinite hangs (e.g., Promise.race with timeout).
- **R-EVDA-007** MUST: Implement cleanup methods for all event-driven components that remove event listeners.

### Scope

**In scope:**
- Playground demo server implementations
- RDP backend client communication layers
- Playwright page automation and browser integration
- WebSocket and real-time communication handlers
- Database query execution and connection management
- External API client implementations

**Out of scope:**
- Pure computational functions without I/O
- Synchronous utility functions for data transformation
- CLI tools where blocking behavior is acceptable
- Test fixtures and mock implementations where simplicity is prioritized

**Exceptions:**
- EXC-001: Initialization code that runs once at startup may use synchronous operations for configuration loading
- EXC-002: Legacy code integration where refactoring cost exceeds benefit

### Verify

```bash
# Check for synchronous I/O operations in integration layer
grep -r 'readFileSync\|writeFileSync' packages/*/src --include='*.ts' | grep -v test | grep -v mock

# Enforce async/await patterns and error handling
eslint --rule 'require-await: error' --rule 'no-async-promise-executor: error' packages/*/src

# Verify event listener cleanup
grep -r 'new EventEmitter' packages/*/src --include='*.ts' -A 5 | grep -c 'removeListener\|off'
```

**Accept when:**
- No synchronous I/O operations (readFileSync, writeFileSync, etc.) found in integration layer code outside of approved exceptions
- All async functions include error handling with try-catch or .catch() handlers
- Event-driven components implement cleanup methods that remove event listeners
- All emitted events are documented with TypeScript interfaces or type definitions
- Timeout wrappers are implemented around external service calls
