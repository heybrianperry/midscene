<rule_activation id="81e56c66-25f9-409f-beca-efc3d5f7691f" title="Adopt Vitest as Standard Test Framework for CI/CD Pipeline: Unit Tests Placed" applies_to="**/*.test.ts">
These rules are ALWAYS ACTIVE for all test files in the monorepo. Vitest is the standard test framework for unit and integration tests across all packages.
</rule_activation>

### Rules

- **R-VITEST-001** SHOULD: Unit tests SHOULD be placed in a tests/unit directory structure to separate them from integration tests.
- **R-VITEST-002** MUST: All test files MUST import test utilities (describe, test, expect) from the 'vitest' package.
- **R-VITEST-003** MUST: Test files MUST follow the .test.ts naming convention.
- **R-VITEST-004** SHOULD: Tests SHOULD be organized in tests/ directories within their respective packages.
- **R-VITEST-005** MUST: A vitest.config.ts or vite.config.ts file with test configuration MUST exist at the package or monorepo root.
- **R-VITEST-006** SHOULD: Shared test setup files SHOULD be maintained (e.g., tests/setup.ts) to configure Vitest globals, mocks, and environment variables.
- **R-VITEST-007** SHOULD: Tests SHOULD be structured for concurrent execution with proper setup/teardown hooks and test isolation.
- **R-VITEST-008** MUST: CI/CD pipelines MUST execute 'vitest run' command and fail builds on test failures.

### Verify

```bash
# Verify Vitest imports in test files
grep -r "from 'vitest'" --include='*.test.ts' || grep -r 'from "vitest"' --include='*.test.ts'

# Verify Vitest configuration exists
find . -name 'vitest.config.*' -o -name 'vite.config.*' | xargs grep -l 'test'

# Verify test file patterns
grep -r "describe\|test\|it\|expect" --include='*.test.ts' | head -5

# Verify test directory structure
find . -type d -name 'tests' | grep -E '(unit|integration)'
```

**Accept when:**
- All test files import test utilities (describe, test, expect) from 'vitest' package
- A vitest.config.ts or vite.config.ts file exists with test configuration
- Test files follow the .test.ts naming convention and are organized in tests/ directories
- Tests are properly isolated and structured for concurrent execution
- CI/CD pipeline successfully executes 'vitest run' without failures

<enforcement>
Claude Code MUST NOT skip or defer verification. All test files MUST comply with Vitest standards before code review approval. Violations block CI/CD pipeline merges.
</enforcement>
