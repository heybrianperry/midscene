<rule_activation id="f63b78a2-3202-490b-aa7f-b25882099a46" title="Adopt Event-Driven Polling with Interval-Based State Synchronization: Event Optimization Utilities" applies_to="**/*">
These rules are ALWAYS ACTIVE for all client-side data access patterns involving periodic state synchronization, event optimization, and keepalive mechanisms across the codebase. Applies to browser extension background scripts, real-time streaming components, event optimization utilities, and any client-side module performing periodic health checks or state synchronization.
</rule_activation>

### Rules

- **R-POLL-001** SHOULD: Event optimization utilities SHOULD batch or throttle high-frequency events to reduce unnecessary data access operations.

### Verify

```bash
# Count setInterval/setTimeout calls without corresponding cleanup
grep -r 'setInterval\|setTimeout' --include='*.ts' --include='*.js' | grep -v 'clearInterval\|clearTimeout' | wc -l

# Verify setInterval calls have corresponding clearInterval in cleanup paths
grep -r 'setInterval' --include='*.ts' --include='*.tsx' -A 10 | grep -c 'clearInterval'

# Check for polling/interval/keepalive tests with cleanup verification
npm run test -- --grep 'polling\|interval\|keepalive' --reporter json | jq '.tests[] | select(.title | contains("cleanup"))'
```

**Accept when:**
- All setInterval and setTimeout calls have corresponding clearInterval/clearTimeout in cleanup paths (component unmount, error handlers, connection close)
- Polling intervals are defined as named constants or configuration values rather than inline magic numbers
- Unit tests exist for polling mechanisms that verify cleanup behavior using fake timers (jest.useFakeTimers or sinon.useFakeTimers)
- Polling intervals include random jitter (±10-20%) to prevent thundering herd problems
- Browser extension keepalive tasks use chrome.alarms API for critical operations
- Memory leak detection tests pass in CI pipeline using heap snapshots

<enforcement>
Claude Code MUST NOT skip or defer verification. All setInterval/setTimeout patterns MUST include cleanup handlers. ESLint custom rules MUST detect uncleaned timers. Code review MUST verify timer cleanup in component lifecycle methods. Memory leak detection failures MUST trigger remediation before merge.
</enforcement>
