<rule_activation id="b4c4cf0f-61b6-4152-8966-a4857e736a93" title="Adopt Backend Client Integration Pattern for External Service Communication: Client Implementations Support" applies_to="**/*">
These rules are ALWAYS ACTIVE for all external service integrations and backend client implementations across the codebase, including RDP backend clients, MCP tools with Puppeteer, Electron packaging scripts, and any new integration with external services, APIs, or backend systems.
</rule_activation>

### Rules

- **R-BACKEND-CLIENT-001** SHOULD: Client implementations SHOULD support configuration injection for endpoints, timeouts, and authentication credentials.

### Scope

**In scope:**
- All RDP backend client implementations in packages/computer
- MCP tool integrations with external services like Puppeteer in packages/web-integration
- Electron packaging scripts that communicate with external build services or APIs
- Any new integration with external services, APIs, or backend systems
- Data access patterns that communicate with remote services

**Out of scope:**
- Internal module-to-module communication within the same process
- Direct database access using ORM or query builders
- File system operations and local resource access
- In-memory data structures and caching layers
- Pure utility functions without external dependencies

**Exceptions:**
- EXC-001: Proof-of-concept or prototype code that will not be merged to production branches
- EXC-002: Third-party SDK already provides a well-designed client abstraction that meets all MUST requirements

### Verify

```bash
# Identify all backend client implementations
grep -r 'class.*Client' packages/computer/src packages/web-integration/src apps/studio/scripts --include='*.ts' --include='*.js' --include='*.mjs'

# Verify typed interfaces are exported
grep -r 'export.*interface.*Client' packages/computer/src packages/web-integration/src --include='*.ts'

# Check integration test coverage
npm test -- --grep 'backend.*client|integration.*test' 2>&1 | grep -E '(passing|failing)'
```

**Accept when:**
- All backend client classes are identified and implement typed interfaces with error handling
- Integration tests exist for client implementations covering connection failures and retry scenarios
- Code review checklist includes verification of backend client pattern compliance for new integrations
- Configuration injection is implemented for endpoints, timeouts, and authentication credentials
- Standardized error handling and retry logic are present in client implementations

<enforcement>
Claude Code MUST verify backend client implementations against these rules before approving external service integrations. Verification is mandatory and MUST NOT be skipped or deferred. CI pipeline enforcement includes automated code review checks, manual architecture review for new integrations, and integration test coverage requirements (minimum 80% for client modules). Pull requests MUST be blocked until architecture review approves integration approach if violations are detected.
</enforcement>
