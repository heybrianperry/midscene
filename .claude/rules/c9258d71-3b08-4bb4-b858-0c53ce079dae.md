These rules are ALWAYS ACTIVE for all files matching event processing pipelines, real-time data stream processors, and keepalive mechanisms that handle external or user-generated events.

### Rules

- **R-DEDUP-001** SHOULD: Cache implementations SHOULD use Map or Set data structures for O(1) lookup performance

### Verify

```bash
# Verify Map or Set usage in cache implementations
grep -r "new Map\|new Set" --include="*.ts" --include="*.js" | grep -i "cache\|dedup\|seen"

# Verify eviction logic is implemented
grep -r "setTimeout\|setInterval" --include="*.ts" --include="*.js" | grep -i "clear\|evict\|cleanup"

# Verify deduplication tests exist
npm test -- --grep "dedup\|duplicate" 2>&1 | grep -E "passing|failing"
```

**Accept when:**
- Event processing components use Map or Set data structures to track processed event identifiers
- Cache implementations include eviction logic (TTL-based or size-based) to prevent unbounded growth
- Unit tests verify that duplicate events are correctly identified and filtered by the cache layer
- Performance tests validate cache lookup times remain under 1ms at expected load

Claude Code MUST NOT skip or defer verification. Code review checklist MUST include verification of cache eviction policies. Unit tests MUST demonstrate deduplication behavior with duplicate event scenarios. Pull requests without proper cache eviction policies MUST be rejected. Production monitoring alerts MUST trigger when cache memory usage exceeds configured thresholds.
</enforcement>
