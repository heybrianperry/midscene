<rule_activation id="670693cc-8826-44f6-8a39-bafd6c12ed68" title="Adopt Vitest as Standard Test Framework for CI/CD Pipeline: Test Suites Organized" applies_to="**/*.test.ts">
These rules are ALWAYS ACTIVE for all test files in the monorepo. Vitest is the standard test framework for all TypeScript test suites, with centralized setup configuration and organized test structure across packages.
</rule_activation>

### Rules

- **R-VITEST-001** MUST: Test suites MUST be organized with a centralized setup file for shared configuration and initialization logic
- **R-VITEST-002** MUST: All test files MUST import test utilities (describe, test, expect) from the 'vitest' package
- **R-VITEST-003** MUST: Test files MUST follow the .test.ts naming convention
- **R-VITEST-004** MUST: Tests MUST be organized in tests/ directories (tests/unit and tests/integration)
- **R-VITEST-005** MUST: A vitest.config.ts or vite.config.ts file with test configuration MUST exist
- **R-VITEST-006** MUST: CI/CD pipelines MUST execute 'vitest run' command and fail builds on test failures
- **R-VITEST-007** SHOULD: Use Vitest's workspace feature for monorepo configurations to enable per-package test configuration while maintaining shared defaults
- **R-VITEST-008** SHOULD: Establish test isolation guidelines and use proper setup/teardown hooks to support concurrent test execution

### Verify

```bash
# Verify Vitest imports in test files
grep -r "from 'vitest'" --include='*.test.ts' || grep -r 'from "vitest"' --include='*.test.ts'

# Verify Vitest configuration exists
find . -name 'vitest.config.*' -o -name 'vite.config.*' | xargs grep -l 'test'

# Verify test file patterns
grep -r "describe\|test\|it\|expect" --include='*.test.ts' | head -5

# Verify centralized setup file exists
find . -path '*/tests/setup.ts' -o -path '*/tests/setup.js'
```

**Accept when:**
- All test files import test utilities (describe, test, expect) from 'vitest' package
- A vitest.config.ts or vite.config.ts file exists with test configuration
- Test files follow the .test.ts naming convention and are organized in tests/ directories
- A centralized setup file (tests/setup.ts) exists for shared configuration and initialization logic
- CI/CD pipeline successfully executes 'vitest run' command without failures
