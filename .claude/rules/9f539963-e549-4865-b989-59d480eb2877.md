<rule_activation id="9f539963-e549-4865-b989-59d480eb2877" title="Adopt Process Lifecycle Management Pattern for External Service Integration: External Process Integrations" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files that spawn, manage, or integrate with external processes and services (XVFB, RDP backends, test servers, Playwright, browser automation, CLI background services).
</rule_activation>

### Rules

- **R-PLCM-001** MUST: All external process integrations MUST implement explicit lifecycle management including spawn, monitor, and terminate phases.
- **R-PLCM-002** MUST: All files that spawn external processes MUST include corresponding termination/cleanup logic.
- **R-PLCM-003** MUST: Integration modules MUST expose consistent start/stop APIs.
- **R-PLCM-004** SHOULD: Create a shared base class or interface defining standard lifecycle methods (start, stop, healthCheck, getStatus).
- **R-PLCM-005** SHOULD: Implement timeout handling using Promise.race or similar patterns with configurable duration values.
- **R-PLCM-006** SHOULD: Use process signal handlers (SIGTERM, SIGINT) to ensure cleanup code runs on unexpected termination.
- **R-PLCM-007** SHOULD: Add structured logging at key lifecycle events (starting, ready, stopping, stopped, error) with correlation IDs.
- **R-PLCM-008** MAY: Consider implementing a process registry or manager class to track all spawned processes and ensure cleanup on application shutdown.

### Verify

```bash
# Check for spawn/exec/fork without cleanup
grep -r "spawn\|exec\|fork" --include="*.ts" --include="*.js" | grep -v "node_modules" | xargs -I {} sh -c 'echo "Checking: {}"; grep -l "terminate\|kill\|cleanup" "{}" || echo "WARNING: No cleanup found"'

# Find all process managers and verify they have cleanup
find . -type f \( -name "*.ts" -o -name "*.js" \) -not -path "*/node_modules/*" -exec grep -l "Process\|Service.*start\|spawn" {} \; | xargs grep -L "stop\|terminate\|cleanup" || echo "All process managers have cleanup"

# Check for lifecycle tests
npm test -- --grep "lifecycle|cleanup|shutdown" || echo "No lifecycle tests found"
```

**Accept when:**
- All files that spawn external processes include corresponding termination/cleanup logic
- Integration modules expose consistent start/stop APIs as verified by interface compliance checks
- Lifecycle tests exist for each external service integration covering startup, health check, and shutdown scenarios
- Process signal handlers are implemented for graceful shutdown
- Structured logging is present at key lifecycle events

<enforcement>
Clause Code MUST NOT skip or defer verification of lifecycle management for any code introducing external process integration. Code review MUST include a checklist verifying lifecycle management. Automated linting rules MUST detect process spawning without cleanup handlers. CI pipeline tests MUST verify graceful shutdown behavior and resource cleanup. PRs introducing violations MUST be blocked until lifecycle management is properly implemented.
</enforcement>
