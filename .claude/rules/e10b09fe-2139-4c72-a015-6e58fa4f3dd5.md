<rule_activation id="e10b09fe-2139-4c72-a015-6e58fa4f3dd5" title="Enforce Environment Variable Validation with Zod Schema for Runtime Configuration: Validation Failures Result" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime configuration and environment variable handling in the codebase. All modules that consume environment variables or external configuration MUST apply the validation rules defined herein.
</rule_activation>

### Rules

- **R-ENV-001** MUST: Validation failures MUST result in clear, actionable error messages indicating which configuration values are invalid and why.

### Verify

```bash
# Detect direct process.env access without validation
grep -r 'process\.env\.' --include='*.ts' --include='*.js' --exclude-dir=node_modules | grep -v 'z\.object\|zod\|schema' | wc -l

# Verify Zod imports are present in configuration modules
grep -r 'import.*zod' --include='*.ts' packages/ | wc -l

# Run configuration validation tests
npm test -- --grep 'configuration.*validation'
```

**Accept when:**
- All configuration modules use Zod schemas for validation with no direct process.env access in application logic
- CI pipeline includes tests that verify configuration validation behavior with invalid inputs
- Linting rules detect and flag direct environment variable access without validation
- Error messages clearly indicate which environment variable failed validation and what the expected format is
- Both the schema type and validated config object are exported from centralized configuration modules

<enforcement>
Claude Code MUST NOT skip or defer verification. All environment variable access MUST be validated through Zod schemas before use in application logic. Violations detected by linting rules or code review MUST block merge and CI build.
</enforcement>
