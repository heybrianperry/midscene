<rule_activation id="be1ba097-b43e-4f6a-8f46-cd5e5f026b43" title="Enforce Environment Variable Validation with Zod Schema for Runtime Configuration: Zod Schemas Define" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime configuration and environment variable handling. All modules that consume environment variables or external configuration MUST apply the validation rules defined herein.
</rule_activation>

### Rules

- **R-ZOD-001** SHOULD: Zod schemas SHOULD define explicit types, constraints, and default values for all configuration parameters.

### Verify

```bash
# Detect direct process.env access without validation
grep -r 'process\.env\.' --include='*.ts' --include='*.js' --exclude-dir=node_modules | grep -v 'z\.object\|zod\|schema' | wc -l

# Count Zod imports in configuration modules
grep -r 'import.*zod' --include='*.ts' packages/ | wc -l

# Run configuration validation tests
npm test -- --grep 'configuration.*validation'
```

**Accept when:**
- All configuration modules use Zod schemas for validation with no direct process.env access in application logic
- CI pipeline includes tests that verify configuration validation behavior with invalid inputs
- Linting rules detect and flag direct environment variable access without validation

<enforcement>
Claude Code MUST verify that environment variable validation follows this ADR. Validation is mandatory for all external configuration sources. Violations must be flagged during code review and CI/CD checks must fail if direct process.env access is detected outside validated configuration modules.
</enforcement>
