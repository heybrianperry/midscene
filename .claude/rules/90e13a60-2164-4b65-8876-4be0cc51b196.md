<rule_activation id="90e13a60-2164-4b65-8876-4be0cc51b196" title="Standardize Environment Variable Configuration for Runtime Secrets Management: Components Support Env" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime components that require configuration or secrets management.
</rule_activation>

### Rules

- **R-ENV-001** MAY: Components MAY support .env files for local development, but these files MUST be excluded from version control via .gitignore
- **R-ENV-002** MUST: All sensitive configuration values (API keys, tokens, passwords) MUST be accessed via process.env rather than hardcoded strings
- **R-ENV-003** MUST: No .env files containing secrets MUST be committed to version control
- **R-ENV-004** SHOULD: Each package SHOULD have documentation listing required environment variables with descriptions and example values
- **R-ENV-005** SHOULD: Configuration modules SHOULD validate required environment variables at startup and provide clear error messages for missing values
- **R-ENV-006** SHOULD: Use TypeScript type definitions to enforce type safety when accessing configuration values
- **R-ENV-007** SHOULD: Provide .env.example as a template for local development setup

### Verify

```bash
# Count process.env usage in TypeScript/JavaScript files (excluding tests)
grep -r 'process\.env\.' --include='*.ts' --include='*.js' | grep -v 'test' | wc -l

# Detect hardcoded secrets (API_KEY, TOKEN, SECRET, PASSWORD patterns not using process.env)
grep -r "['\"](API_KEY|TOKEN|SECRET|PASSWORD)['\"]\s*:\s*['\"]" --include='*.ts' --include='*.js' | grep -v 'process.env' | wc -l

# Verify .env files are in .gitignore
find . -name '.env' -not -path '*/node_modules/*' | xargs grep -l 'API_KEY|TOKEN|SECRET' 2>/dev/null | while read f; do grep -q "^$(basename $f)$" .gitignore || echo "$f not in gitignore"; done
```

**Accept when:**
- All sensitive configuration values (API keys, tokens, passwords) are accessed via process.env rather than hardcoded strings
- No .env files containing secrets are committed to version control (verified by .gitignore entries)
- Each package has documentation listing required environment variables with descriptions and example values
- Configuration modules validate required environment variables at startup and provide clear error messages for missing values
- .env files are excluded from version control via .gitignore
- No hardcoded secret patterns (API_KEY, TOKEN, SECRET, PASSWORD) exist outside of process.env references
