<rule_activation id="069166b7-7ac1-4b25-8257-be9b3cbe449f" title="Adopt Service Client Integration Pattern for Backend Communication: Integration Scripts Implement" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching backend client implementations, build scripts, and service integration code across the system.
</rule_activation>

### Rules

- **R-069-001** SHOULD: Integration scripts SHOULD implement wait mechanisms and health checks to ensure backend service availability

### Verify

```bash
# Find backend client implementations
find . -name '*client*.ts' -o -name '*client*.js' | grep -E '(backend|service)' | head -10

# Verify exported client modules
grep -r 'export.*Client' --include='*.ts' --include='*.js' packages/ apps/ | grep -i backend

# Check build scripts for service coordination patterns
find apps/studio/scripts -name '*.mjs' -exec grep -l 'wait\|health\|ready' {} \;
```

**Accept when:**
- Backend client modules are found in dedicated files with clear naming patterns (e.g., backend-client.ts, service-client.ts)
- Build scripts demonstrate service coordination patterns with wait mechanisms or health checks
- Client implementations export typed interfaces or classes for backend service communication
- Integration scripts include timeout and retry logic for backend service calls
- Service boundaries are clearly defined and enforced through dedicated client modules

<enforcement>
Claude Code MUST verify integration patterns against this ADR during code review. Violations including direct backend calls bypassing client modules, missing health checks in build scripts, or type safety issues in client implementations MUST be flagged for refactoring before merge. Integration tests failing in specific execution contexts (browser, Node.js, Electron) MUST block deployment until resolved.
</enforcement>
