<rule_activation id="e5a99e35-09cd-4a06-a63c-8917e5721a89" title="Adopt Process Lifecycle Management Pattern for External Service Integration: Process Lifecycle Events" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files that spawn or manage external processes, including XVFB, RDP backends, test servers, Playwright, and other external service integrations.
</rule_activation>

### Rules

- **R-PLM-001** SHOULD: Process lifecycle events SHOULD be logged with sufficient detail to support debugging and operational monitoring.

### Verify

```bash
# Check for process spawning without cleanup handlers
grep -r "spawn\|exec\|fork" --include="*.ts" --include="*.js" | grep -v "node_modules" | xargs -I {} sh -c 'echo "Checking: {}"; grep -l "terminate\|kill\|cleanup" "{}" || echo "WARNING: No cleanup found"'

# Find all process managers and verify they have cleanup logic
find . -type f \( -name "*.ts" -o -name "*.js" \) -not -path "*/node_modules/*" -exec grep -l "Process\|Service.*start\|spawn" {} \; | xargs grep -L "stop\|terminate\|cleanup" || echo "All process managers have cleanup"

# Verify lifecycle tests exist
npm test -- --grep "lifecycle|cleanup|shutdown" || echo "No lifecycle tests found"
```

**Accept when:**
- All files that spawn external processes include corresponding termination/cleanup logic
- Integration modules expose consistent start/stop APIs as verified by interface compliance checks
- Lifecycle tests exist for each external service integration covering startup, health check, and shutdown scenarios
- Process lifecycle events are logged with correlation IDs for tracing
- Signal handlers (SIGTERM, SIGINT) are implemented to ensure cleanup on unexpected termination

<enforcement>
Claude Code MUST NOT skip or defer verification of process lifecycle management patterns. All external process integrations MUST include corresponding cleanup logic and lifecycle logging before code review approval.
</enforcement>
