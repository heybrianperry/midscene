<rule_activation id="838c4e28-7f34-44b4-83c0-1d33827b33a6" title="Adopt Event-Driven Async Integration Pattern for Backend Communication: Integration Components Use" applies_to="**/*">
These rules are ALWAYS ACTIVE for all integration components communicating with backend services, RDP clients, and browser automation frameworks.
</rule_activation>

### Rules

- **R-ASYNC-001** MAY: Integration components MAY use Promise-based or Observable-based patterns depending on use case requirements
- **R-ASYNC-002** MUST: Use async/await syntax consistently rather than mixing with raw Promises for better readability
- **R-ASYNC-003** MUST: Implement proper error boundaries with try-catch blocks around all await expressions
- **R-ASYNC-004** MUST: For event-driven components, document all emitted events with TypeScript interfaces or type definitions
- **R-ASYNC-005** SHOULD: Consider using libraries like 'p-queue' or 'p-limit' for controlling concurrency levels in batch operations
- **R-ASYNC-006** SHOULD: Add timeout wrappers around external service calls to prevent indefinite hangs (e.g., Promise.race with timeout)
- **R-ASYNC-007** MUST: Implement cleanup methods for all event-driven components; use weak references where appropriate
- **R-ASYNC-008** MUST NOT: Use synchronous I/O operations (readFileSync, writeFileSync) in integration layer code outside of approved exceptions

### Verify

```bash
# Check for synchronous I/O operations in integration layer
grep -r 'readFileSync\|writeFileSync' packages/*/src --include='*.ts' | grep -v test | grep -v mock

# Verify async/await patterns and error handling with ESLint
eslint --rule 'require-await: error' --rule 'no-async-promise-executor: error' packages/*/src

# Check event listener cleanup in EventEmitter implementations
grep -r 'new EventEmitter' packages/*/src --include='*.ts' -A 5 | grep -c 'removeListener\|off'
```

**Accept when:**
- No synchronous I/O operations (readFileSync, writeFileSync, etc.) found in integration layer code outside of approved exceptions (EXC-001, EXC-002)
- All async functions include error handling with try-catch or .catch() handlers
- Event-driven components implement cleanup methods that remove event listeners
- Async/await syntax is used consistently throughout integration components
- All external service calls include timeout protection
