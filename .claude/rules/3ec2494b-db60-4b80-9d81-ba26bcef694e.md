These rules are ALWAYS ACTIVE for all files matching frontend rendering components, CLI tools with web UI, and integration tests across all packages.

### Rules

- **R-PLAYWRIGHT-001** MUST: E2E tests MUST cover critical rendering paths including navigation (goto), cache functionality, input rendering, and screenshot capabilities.

### Verify

```bash
# Check for Playwright test files
find . -name '*.spec.ts' -path '*/playwright/*' | wc -l | grep -v '^0$'

# Verify @playwright/test dependency
grep -r "@playwright/test" package.json packages/*/package.json

# Verify test scripts reference Playwright
grep -r "test.*playwright" package.json packages/*/package.json | grep -E '(test|e2e)'
```

**Accept when:**
- At least one Playwright test file exists in the project with .spec.ts extension
- Package.json includes @playwright/test as a dependency
- Test scripts reference Playwright for E2E testing execution
- E2E tests cover navigation (goto), cache functionality, input rendering, and screenshot capabilities
- Tests are organized in dedicated directories (e.g., tests/ai/web/playwright/)
- Test file names clearly indicate the rendering scenario being validated

<enforcement>
Claude Code MUST NOT skip or defer verification of Playwright E2E test presence and coverage for frontend rendering components. Violations require architectural review approval with documented justification.
</enforcement>
