<rule_activation id="0b034e2a-6441-41bc-9421-08cc581b9db8" title="Adopt React Component Export Pattern with Named Index Exports: Index Exports Use" applies_to="packages/visualizer/**/*.tsx,packages/visualizer/**/*.ts,packages/recorder/**/*.tsx,packages/recorder/**/*.ts">
These rules are ALWAYS ACTIVE for all React component packages within the monorepo (packages/visualizer, packages/recorder) and apply to TypeScript/TSX component files that define reusable UI components and component directories that contain index.tsx or index.ts files serving as module entry points.
</rule_activation>

### Rules

- **R-EXPORT-001** MUST: Index exports MUST use named exports rather than default exports to enable better IDE autocomplete and refactoring support.

### Verify

```bash
# Count index files in component directories
find packages/*/src/component* -name 'index.tsx' -o -name 'index.ts' | wc -l

# Verify component imports use the index pattern
grep -r "export.*from.*component.*index" packages/visualizer packages/recorder

# Check for restricted direct imports bypassing index files
eslint --rule 'no-restricted-imports: [error, {patterns: ["**/component/*/*.tsx", "!**/component/*/index.tsx"]}]' packages/
```

**Accept when:**
- All component directories in packages/visualizer/src/component and packages/recorder/src/components contain an index.tsx or index.ts file
- Grep search confirms that component imports use the index pattern rather than direct file imports
- ESLint rules pass confirming no restricted direct imports to component implementation files

### Exceptions

- **EXC-001**: A component is explicitly marked as internal-only and documented as not part of the public API
- **EXC-002**: Legacy components being gradually migrated to the new pattern

Exceptions require documentation in code with JSDoc @internal tag or tracking issue link, and must be approved by package maintainer or technical lead in code review.

<enforcement>
Claude Code MUST verify all rules before accepting component exports. ESLint violations block PR merge in CI pipeline. Violations detected in code review must be corrected or formally documented as exceptions with approval.
</enforcement>
