<rule_activation id="63347c01-665e-4e14-a664-e04488382120" title="Adopt Server Initialization Pattern for Development and Testing Environments: Server Initialization Code" applies_to="**/*">
These rules are ALWAYS ACTIVE for all server initialization code in development, testing, and playground environments.
</rule_activation>

### Rules

- **R-SIP-001** MUST: Server initialization code MUST be extracted into reusable modules that can be invoked programmatically from tests, CLI tools, and playground applications.

### Verify

```bash
# Verify server initialization functions are exported from dedicated modules
grep -r "start.*server" packages/*/tests/ apps/*/tests/ --include="*.ts" | grep -E "(export|function|const)"

# Verify proper cleanup logic with server shutdown methods and test lifecycle hooks
grep -r "server\.close\|server\.shutdown\|afterAll\|afterEach" packages/*/tests/ apps/*/tests/ --include="*.ts"

# Find server-related modules in tests and playground directories
find . -name "*server*.ts" -path "*/tests/*" -o -path "*/playground/*" | xargs grep -l "export.*function"
```

**Accept when:**
- Server initialization functions are exported from dedicated modules and imported by test files
- Test files include proper cleanup logic (afterAll/afterEach hooks) that call server shutdown methods
- Server startup functions accept configuration parameters rather than using hardcoded values
- At least 80% of test files and playground applications use the standardized server initialization pattern

<enforcement>
Claude Code MUST NOT skip or defer verification. All server initialization code in development, testing, and playground environments MUST comply with R-SIP-001.
</enforcement>
