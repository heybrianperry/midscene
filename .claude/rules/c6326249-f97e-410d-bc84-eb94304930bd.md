These rules are ALWAYS ACTIVE for all files matching test configurations and CI/CD pipeline definitions across the monorepo.
</rule_activation>

### Rules

- **R-VITEST-001** SHOULD: CI/CD pipelines SHOULD validate the presence and correctness of vitest.config.ts files before test execution
- **R-VITEST-002** MUST: All packages containing tests MUST include a vitest.config.ts file at their root level
- **R-VITEST-003** MUST: Runtime configuration sources MUST be explicitly defined and documented in each vitest.config.ts file
- **R-VITEST-004** SHOULD: Packages SHOULD use TypeScript's 'extends' or Vitest's configuration merging to customize while maintaining base standards
- **R-VITEST-005** MUST: CI/CD pipeline checks MUST validate vitest.config.ts files exist and conform to the standard structure before running tests

### Verify

```bash
# Verify all packages contain vitest.config.ts at root level
find . -name 'vitest.config.ts' -type f | grep -E '(packages/[^/]+/vitest.config.ts)' || echo 'Missing vitest.config.ts files'

# Verify Vitest imports are present in configuration files
grep -r "import.*vitest" packages/*/vitest.config.ts | wc -l

# Verify test execution succeeds with standardized configurations
npm run test -- --reporter=json 2>&1 | jq '.success' || echo 'Test execution validation failed'
```

**Accept when:**
- All packages contain a vitest.config.ts file at their root level
- Test execution in CI/CD pipelines uses the standardized Vitest configurations
- Runtime configuration sources are explicitly defined and documented in each vitest.config.ts file
- All packages with tests pass verification checks in CI/CD pipelines

<enforcement>
Claude Code MUST NOT skip or defer verification of vitest.config.ts presence and correctness. Violations MUST block CI/CD pipeline execution and pull request merges until resolved.
</enforcement>
