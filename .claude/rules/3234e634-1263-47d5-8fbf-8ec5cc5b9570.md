<rule_activation id="3234e634-1263-47d5-8fbf-8ec5cc5b9570" title="Adopt Event-Driven Interval Management with Cleanup Handlers: Cleanup Handlers Idempotent" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`, with particular focus on browser extension background scripts, content scripts, real-time streaming components (MJPEG, WebSocket, SSE), keepalive mechanisms, and event optimization utilities that use setInterval, setTimeout, or requestAnimationFrame.
</rule_activation>

### Rules

- **R-INTERVAL-001** SHOULD: Cleanup handlers SHOULD be idempotent to safely handle multiple invocations without side effects.

### Verify

```bash
# Find setInterval/setTimeout without corresponding cleanup
grep -r 'setInterval\|setTimeout' --include='*.ts' --include='*.tsx' | grep -v 'clearInterval\|clearTimeout' | wc -l

# Run ESLint rules for interval management
eslint --rule 'no-uncleared-intervals' src/

# Run cleanup and teardown tests
npm test -- --grep 'cleanup|teardown|unmount'
```

**Accept when:**
- All files using setInterval or setTimeout have corresponding clearInterval or clearTimeout calls in cleanup handlers
- ESLint rules for interval management pass without violations
- Unit tests verify that cleanup functions properly clear intervals and prevent continued execution
- Cleanup handlers check state before clearing intervals and use defensive programming to ensure idempotency
- Interval IDs are stored in component state or closure scope for accessibility during cleanup

<enforcement>
Claude Code MUST NOT skip or defer verification of cleanup handler idempotency. All interval-based operations MUST have corresponding cleanup handlers that are safe to invoke multiple times without side effects.
</enforcement>
