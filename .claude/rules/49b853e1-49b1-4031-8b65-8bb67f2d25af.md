<rule_activation id="49b853e1-49b1-4031-8b65-8bb67f2d25af" title="Standardize Logging Configuration with Environment-Based Debug Control" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime environments and configuration management implementations within the system, covering packages: playground, computer, web-integration.
</rule_activation>

### Rules

- **R-LOG-001** MUST NOT: Logging configuration MUST NOT require application restart when using dynamic configuration mechanisms, though environment variable changes may require restart.
- **R-LOG-002** MUST: Use environment variables (DEBUG, LOG_LEVEL, VERBOSE) for logging configuration across all runtime components in packages: playground, computer, web-integration.
- **R-LOG-003** MUST: Implement logging initialization code that reads environment variables early in the application lifecycle before any logging occurs.
- **R-LOG-004** SHOULD: Use a consistent logging library across packages that natively supports environment variable configuration (e.g., debug, winston, pino).
- **R-LOG-005** SHOULD: Document all supported logging environment variables in each package's README with examples for common scenarios.
- **R-LOG-006** SHOULD: Implement log sanitization for sensitive fields when debug mode is enabled to prevent exposure of secrets or PII.
- **R-LOG-007** SHOULD: Establish and document standard naming conventions for environment variables (e.g., DEBUG, LOG_LEVEL) across all packages.
- **R-LOG-008** MAY: Implement runtime API endpoints for dynamic logging level changes without restart as a complementary enhancement for long-running services.

### Verify

```bash
# Verify environment variable usage in logging initialization
grep -r 'process\.env\.(DEBUG|LOG_LEVEL|VERBOSE)' packages/*/src --include='*.ts' --include='*.js'

# Count hard-coded logging statements without environment variable guards
grep -r 'console\.log\|logger\.' packages/*/src --include='*.ts' | grep -v 'if.*DEBUG\|if.*process\.env' | wc -l

# Verify debug logging is enabled when DEBUG environment variable is set
docker run --rm -e DEBUG=* <image> npm test 2>&1 | grep -q 'debug:' && echo 'Debug logging enabled'
```

**Accept when:**
- All packages in scope (playground, computer, web-integration) demonstrate environment variable-based logging configuration in their initialization code
- Documentation exists for each package describing supported logging environment variables and their effects
- Integration tests verify that logging behavior changes appropriately when environment variables are set vs. unset
- No hard-coded logging levels exist in production code paths that cannot be overridden by environment configuration
- Environment variable naming conventions are consistent across all packages
- Log sanitization is implemented for sensitive fields in debug mode
