<rule_activation id="296804d9-b485-4de9-a978-175696c26c2b" title="Adopt Vitest as Standard Test Framework for CI/CD Pipeline: Tests Use Vitest" applies_to="**/*.test.ts">
These rules are ALWAYS ACTIVE for all test files in the monorepo. Vitest is the standard test framework for all TypeScript test files across packages.
</rule_activation>

### Rules

- **R-VITEST-001** MAY: Tests MAY use Vitest's concurrent execution features to improve test suite performance
- **R-VITEST-002** MUST: All test files MUST import test utilities (describe, test, expect) from the 'vitest' package
- **R-VITEST-003** MUST: Test files MUST follow the .test.ts naming convention
- **R-VITEST-004** MUST: Tests MUST be organized in tests/ directories (tests/unit or tests/integration)
- **R-VITEST-005** SHOULD: Shared test setup files SHOULD be created (e.g., tests/setup.ts) to configure Vitest globals, mocks, and environment variables
- **R-VITEST-006** SHOULD: Monorepo configurations SHOULD use Vitest's workspace feature for per-package test configuration while maintaining shared defaults
- **R-VITEST-007** MUST: CI/CD pipelines MUST execute 'vitest run' command and fail builds on test failures

### Verify

```bash
# Verify Vitest imports in test files
grep -r "from 'vitest'" --include='*.test.ts' || grep -r 'from "vitest"' --include='*.test.ts'

# Verify Vitest configuration files exist
find . -name 'vitest.config.*' -o -name 'vite.config.*' | xargs grep -l 'test'

# Verify test file patterns
grep -r "describe\|test\|it\|expect" --include='*.test.ts' | head -5
```

**Accept when:**
- All test files import test utilities (describe, test, expect) from 'vitest' package
- A vitest.config.ts or vite.config.ts file exists with test configuration
- Test files follow the .test.ts naming convention and are organized in tests/ directories
- CI/CD pipeline executes 'vitest run' command successfully
- New tests follow Vitest patterns and naming conventions

Claude Code MUST NOT skip or defer verification. All test files MUST comply with Vitest standards before code review approval. CI/CD pipeline blocks merges if tests fail or are missing for new code.
</enforcement>
