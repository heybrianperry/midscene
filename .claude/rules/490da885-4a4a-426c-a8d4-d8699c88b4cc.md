<rule_activation id="490da885-4a4a-426c-a8d4-d8699c88b4cc" title="Adopt React Component Export Pattern with Named Index Exports: Internal Helper Components" applies_to="packages/visualizer/**/*.tsx,packages/visualizer/**/*.ts,packages/recorder/**/*.tsx,packages/recorder/**/*.ts">
These rules are ACTIVE for all React component packages within the monorepo (packages/visualizer, packages/recorder) and apply to TypeScript/TSX component files that define reusable UI components and component directories containing index.tsx or index.ts files.
</rule_activation>

### Rules

- **R-COMP-001** SHOULD: Internal helper components or utilities within a component directory SHOULD NOT be re-exported through the index.tsx unless explicitly part of the public API.

### Verify

```bash
# Count index files in component directories
find packages/*/src/component* -name 'index.tsx' -o -name 'index.ts' | wc -l

# Verify component imports use index pattern
grep -r "export.*from.*component.*index" packages/visualizer packages/recorder

# Check for restricted direct imports bypassing index files
eslint --rule 'no-restricted-imports: [error, {patterns: ["**/component/*/*.tsx", "!**/component/*/index.tsx"]}]' packages/
```

**Accept when:**
- All component directories in packages/visualizer/src/component and packages/recorder/src/components contain an index.tsx or index.ts file
- Grep search confirms that component imports use the index pattern rather than direct file imports
- ESLint rules pass confirming no restricted direct imports to component implementation files

<enforcement>
Claude Code MUST verify all three bash commands pass before accepting component changes. Violations block PR merge in CI pipeline.
</enforcement>
